<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| player screenshot → OCR (on-device) | image bytes decoded and processed locally; the only sanctioned network is the worker's own asset fetch |
| OCR output → wizard inputs | machine pre-fill rendered as editable text, human-verified per step — never a silent authority (D-22 layer 1) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11 | Information disclosure | OcrCapture/CropOverlay | mitigate | no FormData/no upload anywhere (grep gate); screenshots live only in memory (bitmap/canvas) and are dropped after the read; DevTools leak-check repeated at 05-05 UAT |
| T-05-12 | Tampering | applyOcrOutcomes | mitigate | OCR writes go through the SAME central edit wrapper as typing → unchecks the step's verification (stale-confirmation hazard eliminated); create_submission re-validates the final payload server-side |
| T-05-13 | Denial of service | lazy import / worker | accept | CDN or decode failures degrade to D-18 expected-state copy + manual flow (criterion 3 fallback, by design) |
| T-05-14 | Spoofing | supply-chain (worker assets) | mitigate | worker/core self-hosted from the version-locked node_modules copy (not a runtime CDN fetch); langData remains CDN but is data-only and integrity-non-critical (garbage reads are caught by sanity/fix-up) |
</threat_model>
