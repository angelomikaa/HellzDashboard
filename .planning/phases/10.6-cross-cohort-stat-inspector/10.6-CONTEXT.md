# Phase 10.6 — Cross-Cohort Stat Inspector (CONTEXT)

**Owner request (2026-10-30):** "a solution to see the same stat of all the members, independently of class and cohort. This is useful to see if a member might be already cheating their stats. I believe we can find a way to do it in the ranking tab."

## Why a separate lens

Every existing rank surface is cohort-scoped by design: points/OVR compare a member only inside their class+build-role, because a Paladin's PDEF and an Assassin's PDEF are not the same scale. Cheat investigation needs the opposite: ONE stat, EVERY real member, raw values side by side, with both the cohort average (the fair baseline) and the guild average (the "does this number look absurd" signal).

## Locked decisions

| # | Decision |
|---|----------|
| D-10.6-01 | The view lives in the **staff Ranking tab** as a second mode, "Stat entre todos". The Ranking tab is already staff-only; the new RPC enforces `officer/owner + active` internally. |
| D-10.6-02 | **Validated submissions only.** Pending rows stay in Validações; this view is for data already ranked. |
| D-10.6-03 | **Fixtures excluded** (`smoke%` / `dummy-%`). "All members" means all active real members; test data never appears. |
| D-10.6-04 | **Every active real member is returned**, including members with no value for the stat (`value: null`, ordered last) — missing data is information too. |
| D-10.6-05 | Two baselines per row: the **class+role cohort average** (self excluded, same rule as the 0046 anti-cheat flag; displayed only at n ≥ 3) and the **guild average** (all members with a value). |
| D-10.6-06 | Heuristic badges, never verdicts: `cohort_outlier` = ≥ 1.5× the cohort average (red "Acima da coorte"); `guild_outlier` = ≥ 1.5× the guild average (gold "Fora do padrão"). Lower-is-better stats flag at ≤ 0.5×. Ratios suppressed when the baseline average ≤ 0 (negative stats). |
| D-10.6-07 | Server orders by raw value **descending, nulls last** (buffs inflate upward). The client may reverse the array for "Menor primeiro" — display-only view aid, no rank math. |
| D-10.6-08 | No new npm dependencies; append-only migration 0047; bookkeeping row + `notify pgrst`. |
| D-10.6-09 | **Merged-cohort alignment (0048).** Since 0038, Bard and Gypsy are ONE `Artista` stats cohort with one key config. Every 0046/0047 cohort scope must use `public.cohort_group(char_class)` like the seven 0038 rank RPCs — otherwise a Menestrel is compared only to Menestrels and `ovr_projection` has no key config to project with. 0048 is a corrective append-only migration, no payload/threshold change. |

## Known limitation (recorded for the owner)

The guild-wide badge is intentionally sensitive and WILL flag legitimate builds on skewed stats: `crit_dmg` has a guild average of ~5 because most members have 0, so a 53-crit-dmg build reads 10.5× and gets the gold badge. The red cohort badge is the stronger signal; the gold badge means "eyeball this", not "cheating". The panel copy says so explicitly.
