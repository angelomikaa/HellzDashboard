<feature>
  <name>Rank math executable spec: percentilePoints + ovrFromPoints</name>
  <files>src/lib/rankMath.ts, src/lib/rankMath.test.ts</files>

  <behavior>
Formula decisions (locked by this spec — implement exactly):

**1. `percentilePoints(ownValue: number, others: number[])`** where `others` = cohort values EXCLUDING the caller's own entry.
- `n = others.length + 1` (the caller is a cohort member)
- `dataSufficient = n >= 3` (D-12: at n=3 the formula yields a genuine middle value 0/49.5/99; n=2 would be binary)
- If NOT dataSufficient → return `{ points: null, dataSufficient: false }` (RNK-05 / D-13: points omitted, flag explicit)
- Otherwise:
  - `countBelow = others.filter(v => v < ownValue).length`
  - `countTies = others.filter(v => v === ownValue).length`
  - `points = ((countBelow + countTies / 2) / (n - 1)) * 99` — i.e. `(countBelow + countTies/2) / others.length * 99`
  - Return `{ points, dataSufficient: true }`
- Tie semantics = AVERAGE RANKS (research standard, 03-CONTEXT discretion item — CONFIRMED HERE): tied players each get the average of the points their occupied positions would yield. Equal values → equal points, always.
- Return type: `{ points: number | null; dataSufficient: boolean }`

**2. `ovrFromPoints(points: number[]): number`** (D-09 + D-10):
- REQUIRES `points.length === 6` — throw `RangeError('ovr requires exactly 6 key-stat points')` otherwise (D-11 all-6-or-nothing is the CALLER's gate; the function itself is strict)
- Returns `51 + (mean(points)) * (48 / 99)` — LINEAR RESCALE, not a clamp (D-10): worst player in class = 51, best = 99, bottom-half players keep differentiation
- Returns the UNROUNDED decimal (rounding is a Phase 4 display concern)

**3. `export const MIN_COHORT_SIZE = 3`** (D-12 single source of truth)

Worked examples (MUST all be tests):
| ownValue | others | expected points | why |
|----------|--------|-----------------|-----|
| 50 | [10,20,30,40] | 99 | best of 5, distinct |
| 10 | [20,30,40,50] | 0 | worst of 5 |
| 30 | [10,20,40,50] | 49.5 | middle of 5 |
| 20 | [10,30] | 49.5 | n=3 middle (0/49.5/99 trio, D-12) |
| 10 | [10,5] | 74.25 | tie at top of 3: (1 + 0.5)/2 × 99 |
| 20 | [20,10,30] | 49.5 | tie in middle of 4: (1+0.5)/3 × 99 |
| 7 | [7,7] | 49.5 | all three tied: (0 + 1)/2 × 99 |
| any | [] (n=1) | null | dataSufficient false |
| any | [x] (n=2) | null | dataSufficient false |

OVR examples (MUST all be tests):
- six 99s → 99.0 exactly
- six 0s → 51.0 exactly (the floor — never below)
- [99,99,99,0,0,0] → mean 49.5 → 51 + 49.5×48/99 = **75.0 exactly**
- [99,99,99,49.5,99,99] → mean 90.75 → 51 + 90.75×48/99 = **95.0 exactly**
- [0, 74.25, 0, 49.5, 0, 0] → mean 20.625 → 51 + 20.625×48/99 = **61.0 exactly**
- length 5 → throws RangeError
- length 7 → throws RangeError
  </behavior>

  <implementation>
Single self-contained module, no imports, no I/O, no React. Numeric arithmetic only — floating point is fine at these magnitudes (values ≤ 99, means of 6). Use `Number` math directly; do not round internally. JSDoc-comment each exported symbol citing the decision IDs (RNK-04, D-09, D-10, D-11, D-12) and stating that production rank truth lives in Postgres RPCs.
  </implementation>
</feature>
