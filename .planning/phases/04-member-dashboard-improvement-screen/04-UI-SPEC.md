## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-rolled components — shadcn deliberately NOT initialized) |
| Preset | not applicable |
| Component library | none — React 19 function components, Tailwind v4 utilities only |
| Icon library | none — text-first UI; the one icon (collapse chevron) is an inline SVG |
| Font | System UI stack (Tailwind default sans — no custom family declared in `@theme`) |

**Why no shadcn:** the project has an established, owner-approved manual design system — `@theme` tokens in `src/index.css` (defined in Phase 1 with tier tokens *explicitly reserved for Phase 4+*) plus four shipped pages sharing concrete patterns (44px `h-11` controls, `rounded-md/lg`, `border-line`, `bg-surface`, `focus-visible:ring-accent`, enumeration-safe pt-BR error copy). The hand-rolled stack is a locked project decision. Registry safety gate: **not applicable** (no registry, no third-party blocks).

**Token wiring:** tier tokens are consumed as Tailwind v4 utilities generated from `@theme` — `border-tier-bronze|silver|gold|platinum`, `text-tier-*`, `bg-tier-*` (per 04-CONTEXT integration note). No new tokens are needed for this phase; the palette below is complete.

## Spacing Scale

Declared values (all multiples of 4 — Tailwind's 4px base):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon/badge gaps, legend dot gaps (`gap-1`), badge/chip vertical padding (`py-1`) |
| sm | 8px | Legend line spacing, hero→legend gap (`mt-2`), inline chip horizontal padding (`px-2`) |
| md | 16px | Stat-card padding (`p-4`), grid gaps (`gap-4`), strip container padding (`p-4`) |
| lg | 24px | Section separation (`mt-6`), OVR hero padding (`p-6`), empty-state block |
| xl | 32px | Empty-state vertical padding (`py-8`) |
| 2xl | 48px | Not used this phase (reserved) |
| 3xl | 64px | Not used this phase (reserved) |

**Exceptions (declared):**
- **44px touch targets** (`h-11`) on every interactive element: collapse group headers, "Foco de melhoria" strip items, empty-state CTA — matches the existing App nav / buttons / selects pattern (mobile-first: Ragnarok Origin players are on phones).
- **12px horizontal padding** (`px-3`) on FocusStrip items — matches the shipped `h-11` control pattern (App.tsx nav buttons, selects, list rows all use `px-3`; only filled CTAs use `px-4`). 12px is a multiple of 4 but sits off the declared scale steps; kept for consistency with the established design system.
- 12px legend color dots (`h-3 w-3`) — decorative, not interactive.

The dashboard renders inside App's existing `max-w-3xl px-4 py-6` main wrapper (src/App.tsx line 111) — no new page-level spacing is introduced.

## Typography

Exactly 4 sizes, 2 weights. All map to existing Tailwind classes used across shipped pages.

| Role | Size | Weight | Line Height | Classes |
|------|------|--------|-------------|---------|
| Display — OVR hero number | 48px | 600 | 1.0 | `text-5xl font-semibold leading-none` |
| Heading — hero character name, group headings, empty-state title | 20px | 600 | 1.2 | `text-xl font-semibold` |
| Body — stat card own value, percentile phrase, buttons, CTA | 16px | 400 | 1.5 | `text-base` (own value additionally `font-semibold`) |
| Caption — Média/Melhor line, FLAT/PERCENTUAL tag, badges, legend, chips | 14px | 400 (600 inside badges/chips) | 1.5 | `text-sm` |

**Rules:**
- Stat card own value is the "big" element of D-08: 20px/600 (`text-xl font-semibold text-content`), never larger — the OVR hero number is the only 48px element on the page.
- Tier-colored text (points badge, hero OVR number) is always `font-semibold` — required for AA contrast at small sizes (see Color).
- No other sizes or weights exist in this phase. No italics.

## Color

60/30/10 is already tokenized in `src/index.css` — restated as the binding contract:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0D1117` (`bg-dominant`) | Page background (App root — already set) |
| Secondary (30%) | `#161B22` (`bg-surface`) | OVR hero, stat cards, strip items, empty-state card |
| Line | `#30363D` (`border-line`) | Card/group borders (default), dividers, chips |
| Accent (10%) | `#E3B341` (`bg/text/border-accent`) | See reserved list below |
| Destructive | `#F85149` (`text-destructive`) | Error alert text ONLY (no destructive actions exist this phase) |
| Content | `#E6EDF3` (`text-content`) | All primary text, own values, headings |
| Muted | `#8B949E` (`text-muted`) | Média/Melhor line, tags, legend text, all disabled/grayed states |

**Accent reserved for (exhaustive list — never "all interactive elements"):**
1. Empty-state primary CTA button (`bg-accent text-accent-foreground` — the ONE filled-accent element on the page)
2. "Foco de melhoria" strip heading text (`text-accent` — the improvement loop is the core-value wayfinding)
3. `focus-visible` rings on all interactive elements (existing project-wide pattern)
4. Active tab underline (existing App pattern — unchanged by this phase)

**Accent is NOT used for:** stat card borders, points badges, OVR hero styling, or the tier legend — those belong to the tier palette. Tier gold and accent gold are **two different tokens with two different jobs** (`#E9B44C` = achievement, `#E3B341` = interaction); they are never interchangeable.

### Tier palette (SHWC-01 — color-only communication, D-03)

| Tier | Token | Hex | Legend label (pt-BR) |
|------|-------|-----|----------------------|
| Bronze | `tier-bronze` | `#B87333` | Bronze |
| Silver | `tier-silver` | `#B8C0CC` | Prata |
| Gold | `tier-gold` | `#E9B44C` | Ouro |
| Platinum | `tier-platinum` | `#D7E3F0` | Platina |

**Contrast (accepted exceptions, recorded honestly):** actual WCAG ratios on `bg-surface`: bronze `#B87333` ≈**2.98:1** (bronze's own luminance caps it at 3.01:1 even against black — it cannot reach AA for text), muted `#8B949E` ≈**3.53:1** (a pre-existing project-wide pattern this phase inherits), silver ≈7.71:1, gold ≈7.83:1, platinum ≈13.45:1. **Accepted exception:** bronze and muted are used for badge/chip/caption text whose meaning is triply redundant (inline legend + numeric points badge + percentile phrase, per Accessibility), so the tier signal survives even where the color's contrast is weak. Do NOT cite font weight as an AA justification for these two colors. If bronze text is ever used outside the redundant-badge context, introduce a lightened bronze tint first.

## Copywriting Contract

All strings are final pt-BR copy. Error copy is **enumeration-safe** — raw server text is never rendered (KeyStatsPage pattern).

| Element | Copy |
|---------|------|
| Primary CTA (empty state) | **Enviar Status** (verb + noun; jumps to the Enviar Status tab — D-13) |
| Empty state heading | Nenhum status enviado ainda |
| Empty state body | Envie seus status para ver seus cards, sua posição na classe e o que melhorar. |
| Error state (network/server) | Não foi possível conectar ao servidor. Verifique sua conexão e tente novamente. |
| Error state (session/permission) | Sua sessão expirou ou você não tem permissão. Entre novamente. |
| Loading | Carregando… |
| Group headings | Geral · Quasi · Especial (exact wizard/Stats-Chave labels — 03-04 decision) |
| Points badge | the integer only, e.g. `72` (`Math.round(points)`, tier color carries meaning; no "pts" suffix) |
| Percentile phrase — top half (points ≥ 50) | Você está entre os {B}% melhores em {label}. |
| Percentile phrase — bottom half (points < 50) | Você está entre os {B}% piores em {label}. |
| Comparison line (D-12) | Média: {class_average} · Melhor: {best} — muted numbers only, formatted with `formatStatValue(value, value_type)` |
| Missing value (D-14) | Sem registro (in the value slot; card grayed) |
| Insufficient chip (D-15) | Dados insuficientes (muted chip in the badge slot) |
| OVR hero insufficient | Big slot: `—` + line: OVR indisponível — sua classe e função precisam de pelo menos 3 jogadores com status enviados. |
| OVR hero insufficient — no class set | Slot: `—` + line: Sem classe definida — peça a um oficial para registrar sua classe e função. (hero class line shows `—`) |
| Improvement strip heading | Foco de melhoria |
| Tier legend | Bronze · Prata · Ouro · Platina |
| Value type tag (D-08) | `FLAT` or `PERCENTUAL` — uppercase `text-sm text-muted` tag beside the label |
| Destructive confirmation | none — this phase is a read-only dashboard; no destructive actions exist |

**Phrase banding formula (discretion resolved — prescriptive):** with `p` = points (0–99, unrounded from RPC):
- `p ≥ 50` → melhores, `B = 10 × ⌈(100 − p) / 10⌉`
- `p < 50` → piores, `B = 10 × ⌈p / 10⌉`
- Clamp `B` to `[10, 90]` (never "0%" or "100%").

This satisfies CMP-02's literal example: points ≤ 30 → "Você está entre os 30% piores em CRIT" (the class is established once by the hero line — no per-card class repetition, per D-10's locked template). 10% steps keep the phrase stable as the cohort shifts (D-10). Tone is direct/neutral — factual, no softening (D-11).

## Data Contract (what the UI renders — `my_report()` RPC, 0009 §4)

Add to `src/lib/api.ts` following the `fetchClassTop5` wrapper precedent (`POST /rpc/my_report`, empty JSON body — identity comes from the JWT):

```ts
export interface MyReportStat {
  stat_key: string
  label: string
  group_name: 'general' | 'quasi' | 'special'
  value_type: 'flat' | 'percentual'
  own_value: number | null
  class_average: number | null
  best: number | null
  points: number | null        // null when data_sufficient=false or own_value=null
  data_sufficient: boolean     // cohort n >= 3 (03-CONTEXT D-12)
}

export interface MyReport {
  char_class: string | null
  char_function: 'tank' | 'dps'
  stats: MyReportStat[]        // always all 57 catalog entries, ordered group_name, label
  ovr: { value: number | null; data_sufficient: boolean }
}

export async function fetchMyReport(session: NeoFootSession): Promise<MyReport>
```

**Hard rules (RNK-02 / CMP-03 / AGENTS.md):**
- The response contains **no key-stat identity and no `is_key` flag** — the dashboard renders it verbatim and must never derive, hint at, request, or infer which stats are key. No DOM attribute, class name, tooltip, or query may encode key-stat identity.
- **No client-side rank math.** Points/OVR arrive opaque and precomputed; nothing imports `src/lib/rankMath.ts`. The only math in the UI is the phrase banding + badge rounding above (presentation of the given number).
- The dashboard makes exactly **one** data call (`fetchMyReport`); it never fetches other members' rows (CMP-03 — aggregates only; the RPC is the sanctioned boundary).
- Compute-on-read: fetch on mount only, no polling, no caching of OVR/points. Switching tabs unmounts the dashboard (App renders conditionally) — returning to Painel refetches. That is the refresh mechanism; no refresh button.

## Layout & Grid (CMP-01 — mobile-first)

Page structure, top → bottom (all inside App's existing `max-w-3xl` wrapper):

```
┌──────────────────────────────────────────┐
│ OvrHero   (tier border, bg-surface p-6)  │
│ TierLegend           (mt-2, one line)    │
│ FocusStrip           (mt-4, when ≥1 elig)│
│ Geral      (mt-6, open)   ┐              │
│ Quasi      (mt-6, collapsed)├ 57 cards   │
│ Especial   (mt-6, collapsed)┘            │
└──────────────────────────────────────────┘
```

- **Grid (D-06):** `grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3` inside each group. 1 col phones → 2 from `sm` → 3 at the desktop `max-w-3xl` container. Readability over density; no horizontal scroll.
- **Collapsible groups (D-05):** Geral open by default; Quasi and Especial collapsed. Header = full-width `h-11` button, `flex items-center justify-between`, label `text-sm font-semibold` + inline-SVG chevron rotating 90° when open (`transition-transform`), `aria-expanded` + `aria-controls`; body is the grid, hidden when collapsed.
- **Empty state replaces everything below the fold** — no hero, no legend, no grid (D-13: message + CTA, not a grayed grid).

### StatCard anatomy (D-08 — full info, one glance, no tap-to-expand)

```
┌─ border rounded-lg bg-surface p-4 ──(border-tier-X)─┐
│ CRIT                    [PERCENTUAL]                 │  text-sm label · text-sm muted tag
│ 1.234                    [72]                        │  text-xl/600 value · tier badge (px-2 py-1, text-sm/600, border+text tier color)
│ Você está entre os 20% melhores em CRIT.            │  text-sm text-muted (phrase, own label)
│ Média: 1.234 · Melhor: 9.876                         │  text-sm text-muted (D-12)
└──────────────────────────────────────────────────────┘
```

- Card border: `border` (1px) tier-colored when points exist; the hero gets the heavier `border-2` metallic emphasis (discretion: weight hierarchy, not decoration).
- Points badge = tier-colored **border + text** on surface (e.g. `rounded-full border border-tier-gold px-2 py-1 text-sm font-semibold text-tier-gold`) — no filled tier backgrounds (fills would break the 60/30/10 balance across 57 cards).

### FocusStrip (D-16 — the improvement loop)

`bg-surface rounded-lg border border-line p-4`; heading `Foco de melhoria` in `text-sm font-semibold text-accent`; three items in a row that wraps (`flex flex-wrap gap-2`). Each item = full `h-11` button (`rounded-md border border-line bg-surface px-3`): stat label (`text-sm text-content`) + points value (`text-sm font-semibold text-tier-*`). Whole item is the jump affordance.

**Selection rule (discretion resolved — ties & edges):**
1. Eligible = stats with `points !== null` (data sufficient AND own value present).
2. Sort ascending by points; ties broken by `stats[]` array order (stable).
3. Take the first 3. Show 1–2 if only that many are eligible. **Hide the strip entirely when 0 are eligible.**

**Jump interaction:** `onJump(statKey, group)` → parent sets that group's `open=true` → after the render (`requestAnimationFrame`), `document.getElementById("stat-"+statKey)` → `scrollIntoView({ behavior: "smooth", block: "center" })` → `.focus()`. The card div carries `tabIndex={-1}` + `focus:outline-none focus:ring-2 focus:ring-accent` (programmatic-focus ring; cards are never in the tab order).

## State Matrix

| State | Detection | Rendering |
|-------|-----------|-----------|
| Loading | report === null, no error | `Carregando…` (`text-base text-muted`) |
| Error | ApiError from fetchMyReport | `role="alert" aria-live="polite"` + `text-sm font-semibold text-destructive`; unauthorized → session copy, else network copy (KeyStatsPage mapping) |
| Empty — no submission | every `stat.own_value === null` | Empty-state card (heading + body + **Enviar Status** CTA → `onNavigate('submit')`). Nothing else renders (D-13) |
| Success | report loaded, ≥1 own value | Hero + legend + strip (if eligible) + 57 cards |
| Sem registro (D-14) | `own_value === null`, player has other values | Card stays in place, whole card `opacity-60`; value slot shows **Sem registro** (`text-base text-muted`); no badge, no phrase; Média/Melhor still render |
| Dados insuficientes (D-15) | `own_value !== null && data_sufficient === false` | Card normal but `border-line`; own value + Média/Melhor render (values are never omitted — 03-CONTEXT D-13); badge slot → muted chip **Dados insuficientes** (`rounded-full border border-line px-2 py-1 text-sm text-muted`); no phrase |
| OVR insufficient (D-07/D-15) | `ovr.data_sufficient === false` | Hero `border-line`, `—` slot + explanation line (copy table) |
| No class set | `char_class === null` | Hero class line `—` + "Sem classe definida" explanation; cards render own values with `Média: — · Melhor: —` (57-card shape stays stable) |

Priority: error > loading > empty > success-with-variant-states (per-card, not per-page — the 57-stat shape is always stable once any value exists).

## Accessibility & Interaction Contract

- Every interactive element (CTA, collapse headers, strip items) is `h-11` (44px) with `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent` — the established project pattern.
- Collapse: `aria-expanded` on the header button, `aria-controls` → group body id; chevron is `aria-hidden`.
- Phrase and Média/Melhor lines are plain text — screen readers get the full comparison without color. Color-only tier meaning (D-03) is backed by the legend + the numeric badge + the phrase (three redundancies; never color alone).
- `aria-busy` while fetching (KeyStatsPage pattern). Error alerts use `role="alert" aria-live="polite"`.
- No hover-only affordances (mobile-first); strip items communicate tappability by being full buttons.
- Values use `formatStatValue` (pt-BR `1.234.567` / `,` decimals / trailing `%`) — never raw JSON numbers.

## Security Rules (non-negotiable, bind the executor)

1. **RNK-02:** nothing in the dashboard may expose, hint at, or derive key-stat identity — the UI renders `my_report` verbatim; points/OVR are opaque inputs to badges/phrases.
2. **CMP-03:** members see aggregates only — the dashboard performs no query for other individuals and renders no other individual's values.
3. No client-side rank math; no import of `rankMath.ts`; no caching of points/OVR.
4. The Painel tab is for every role — no gating is added or removed (tab UX-only pattern; enforcement is server-side, unchanged).
