## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Tampering | bypassing the review gate via DevTools/direct RPC call | accept-by-design at UI, mitigate at server | the gate is UX; the server re-validates (unknown_stat_key rejection, JWT-derived member_id, catalog FK) — junk values are possible by design (free-text stats are the source of truth; officer validation lands in Phase 6, statuses stay 'pending' until then) |
| T-02-14 | Tampering | double-submit / duplicate stats in one payload | mitigate | RPC `insert ... select` + `unique(submission_id, stat_key)` constraint → duplicates error the whole transaction (atomic) |
| T-02-15 | Repudiation | player denies a submission | accept | submissions carry member_id + submitted_at server-side (auth-sourced); officer queue (Phase 6) adjudicates |
| T-02-16 | Information Disclosure | screenshots of member devices | mitigate | no upload path exists at all (D-10): no FormData, no Storage calls — acceptance criterion greps prove it |
| T-02-17 | Spoofing | classless member submitting to poison per-class ranks | accept (Phase 3 guard) | UX blocks classless members; Phase 3 RPCs rank within class and simply have nothing to compute for classless rows |
</threat_model>
