**Status:** complete — code + tests green, migration 0046 **applied live and verified 2026-10-30**.

## What shipped

### Server — `supabase/migrations/0046_anti_cheat_guardrails.sql`

- **`submission_provenance`**: append-only per-input OCR audit (`source` = `ocr` / `ocr_edited`, `ocr_value`, `final_value`). RLS enabled with no policies; clients have no read path.
- **`create_submission` v4**: optional `p_provenance` array. Validates keys (catalog stats + the two equipment tooltip inputs), sources, numeric values, uniqueness, and that every catalog entry references a submitted stat. Catalog `final_value` is re-derived from `p_stats` — the client cannot forge it. Drops the 2-arg overload (PostgREST resolution), keeps the default for old clients.
- **`defense_cohort_baselines()`**: member-callable aggregates for `rpdef`, `rmdef`, `equip_pdef_pct`, `equip_mdef_pct` over the caller's class+build-role cohort (latest validated per active member, caller excluded, n ≥ 3).
- **`ovr_projection()`**: internal review-only OVR calculator using the Phase 9/10.1 value-proportional formula copied verbatim from `role_rank` (0036). Exact for the member's own projected points.
- **`submission_anti_cheat()`**: defense spikes ≥ 1.5×, OCR edits with original/final/delta, projected OVR swing; `flagged` = spike or ≥ 8-point swing with unchanged class/build-role.
- **`officer_queue()` v2**: additive `anti_cheat` per row, everything else untouched.

### Client

- `src/lib/api.ts`: `SubmissionProvenanceEntry`, `AntiCheatFlags` (+ spike/override/swing types), `p_provenance` on `createSubmission`, `fetchDefenseBaselines()`. `OfficerQueueRow.anti_cheat` is optional so a bundle survives the deploy window.
- `src/features/submit/antiCheat.ts`: `defenseSpikeWarnings` (1.5× mirror), `buildProvenance` (numeric equality → `ocr`; different number → `ocr_edited`; equipment keys included), `ovrSwingFlagged`, locked thresholds.
- `src/features/submit/AntiCheatWarnings.tsx`: player notice on the Especial step and above Enviar; the submission remains allowed and is marked for review.
- `src/features/submit/SubmitPage.tsx`: OCR trace ref per step; tooltip origin plumbing; baselines fetched in parallel and swallowed on failure; `p_provenance` sent on submit.
- `src/features/submit/DefenseStep.tsx`: reports `user` / `ocr` / `ocr_failed` origins for the transient Equipment PDEF/MDEF values.
- `src/features/admin/AntiCheatPanel.tsx`: officer evidence panel (spikes with baseline/ratio/n, OCR edits original→final + delta %, OVR previous→projected).
- `src/features/admin/ValidacoesPage.tsx`: `⚠ Revisar` chip on flagged rows; panel above the stat groups when expanded.
