# Phase 10.5 Plan 01 — Anti-Cheat Guardrails

**Requirements:** CHEAT-01..CHEAT-05
**Depends on:** Phase 9.1 (`rpdef`/`rmdef` catalog), Phase 10.1 (canonical value-proportional rating formula), Phase 8 (identity on submissions)
**Migration:** `0046_anti_cheat_guardrails.sql`

## Goal

A buffed submission can no longer silently inflate the ranking: the server flags defense values at or above 1.5× the class+role cohort average, records which OCR-read fields the player altered, and warns officers when a submission swings the OVR by 8+ points without a class/role change — while still saving the submission pending for a human decision.

## Tasks

1. **Migration 0046 (server foundation)**
   - `submission_provenance` (append-only, RLS deny-all): `input_key`, `source`, `ocr_value`, `final_value`.
   - `create_submission` v4: optional `p_provenance`; catalog final values re-derived from `p_stats`; `invalid_provenance` guards; drops the 2-arg overload.
   - `defense_cohort_baselines()`: member-callable aggregates for the four defense stats (class+role, self excluded, n ≥ 3).
   - `ovr_projection(member, class, function, stats)`: internal, the 0036 value-proportional formula; exact for the member's own points.
   - `submission_anti_cheat(submission)`: spikes, OCR overrides, projected OVR swing, `flagged`.
   - `officer_queue()` v2: additive `anti_cheat` object per row.
   - Bookkeeping row + `notify pgrst, 'reload schema'`.

2. **Client data + pure logic**
   - `api.ts`: `SubmissionProvenanceEntry`, `AntiCheatFlags` types, `p_provenance` on `createSubmission`, `fetchDefenseBaselines()`.
   - `antiCheat.ts`: 1.5× warning builder, OCR provenance builder, locked thresholds, `ovrSwingFlagged`.
   - `AntiCheatWarnings.tsx`: player-facing buff notice.

3. **Submit wizard (provenance + warning)**
   - `SubmitPage` keeps an OCR trace ref; every step read replaces its own trace; tooltip reads are traced through `DefenseStep` origins (`ocr` / `user` / `ocr_failed`).
   - Baselines fetched in parallel and never block the wizard.
   - Warnings shown on the Especial step and above Enviar; submission still allowed.
   - `p_provenance` attached on send.

4. **Officer review**
   - `AntiCheatPanel` on the expanded Validações row: spikes with baseline/ratio/n, OCR edits with original→final and delta %, OVR previous→projected.
   - Collapsed row shows a `⚠ Revisar` chip when the server flags the submission.

5. **Tests + gates**
   - New pure tests for the spike boundary, provenance source classification, tooltip inputs and locked thresholds.
   - Panel render tests (spike / OCR edit / swing / changed class / no-flags / old-server absence).
   - `createSubmission` payload tests for `p_provenance`.
   - Full suite, `tsc -b`, `oxlint`, `vite build`.

## Success criteria

1. `rpdef`/`rmdef`/`equip_pdef_pct`/`equip_mdef_pct` at ≥ 1.5× the class+role cohort average appear in `defense_spikes` and set `flagged`.
2. Every input the OCR read filled is either `ocr` or `ocr_edited`; edited rows carry the printed value and the final value; catalog final values cannot be forged.
3. A pending submission that would move OVR by ≥ 8 points with unchanged class/function shows the swing and sets `flagged`; a class/role change suppresses that warning.
4. The player sees the buff warning before sending; the submission is still saved pending.
5. Members can read aggregates only; `submission_provenance` has no member read path; no key-stat config appears in any payload.
