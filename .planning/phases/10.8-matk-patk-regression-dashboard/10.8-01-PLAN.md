# Phase 10.8 Plan 01 — MATK/PATK Regression Dashboard

**Requirements:** MREG-01, MREG-02, MREG-03, MREG-04
**Depends on:** Phase 10.6 (Stat entre todos tab), 10.7 (statistical modules), read-only live database
**Migration:** `0051_regression_dataset.sql` (read-only RPC)

## Goal

Add a regression dashboard inside Ranking → Stat entre todos that uses the real validated records to explore MATK/PATK relationships, fit OLS + Theil–Sen curves with confidence bands, classify members as NORMAL / POSSIBLE_BUFF / INCONCLUSIVE under the +35 p.p. hypothesis, and report the data limitations honestly.

## Tasks

1. **Migration 0051**
   - `stat_regression_dataset()` — staff-only, read-only: latest validated `matk`, `equip_matk_pct`, `patk`, `equip_patk_pct` per active real member, coverage counts, history count, and a `fields` map marking Equipment/Base flat MATK/PATK as unavailable.
   - Grants, comment, bookkeeping, pgrst reload. No table writes.
2. **Statistical core (`regression.ts`)**
   - OLS (R², RMSE, slope/intercept 95% CI), Theil–Sen, MAD scale, LOO CV, influence sensitivity.
   - Four models: `matk_pct`, `patk_pct`, `ratio_diff`, `matk_patk`.
   - +35 p.p. classification with configurable thresholds.
   - External reference-pair residuals + illustrative classification.
3. **Dashboard**
   - Sub-view toggle inside Stat entre todos: Tabela | Regressão.
   - SVG scatter charts (no dependency): MATK×MATK%, PATK×PATK%, MATK/PATK×Δ%, MATK×PATK, residual histogram.
   - OLS + Theil–Sen lines, 95% CI band, clickable points, selected-member detail card, reference diamonds.
   - Model selector, statistics panel, classification table, data-limitation panel, method/assumptions.
4. **Tests + gates**
   - `regression.test.ts`: OLS/Theil–Sen/MAD/LOO, +35 classification (MATK% and ratio models), small-sample INCONCLUSIVE, control model, reference classification.
   - `regressionDatasetMigration.test.ts`: staff-only/read-only/fields/coverage/bookkeeping.
   - Full suite, `tsc -b`, `oxlint`, `vite build`.
5. **Live verification**
   - Apply 0051; call the RPC with an owner JWT; confirm 30 members and coverage.
   - Confirm the reference pair is recognized on MATK×MATK% (z −2,65 declared / +0,40 debuffed; score 2,26).
   - Confirm no current member is forced into POSSIBLE_BUFF.

## Success criteria

1. The dashboard shows only real DB points (no fabricated samples) and labels Equipment/Base flat MATK/PATK as unavailable (MREG-01).
2. MATK×MATK%, PATK×PATK%, ratio and MATK×PATK scatters render with OLS/Theil–Sen, CI, n and R²; residual histogram shows robust z bands (MREG-02).
3. The classification returns NORMAL/POSSIBLE_BUFF/INCONCLUSIVE with member, declared/inferred MATK%, observed/expected MATK, residual and score; scores are labeled as anomaly signals, not cheat probabilities (MREG-03).
4. The owner reference pair is recognized as POSSIBLE_BUFF on MATK×MATK% with the explicit missing-PATK caveat; the default ratio model shows no forced second population (MREG-03).
5. Read-only RPC, staff-only gate, fixtures excluded, no key-stat leak, no new npm dependencies (MREG-04).
