The MATK/PATK ratio vs the percentage difference is the strongest and is the default classification model: it uses PATK as a physical control for class/gear differences. MATK and PATK are not interchangeable; the relationship is measured, not assumed.

## +35 p.p. hypothesis

For the MATK models, the declared x is compared with `x−35`:
- `resid_declared = y − f(x)`
- `resid_debuffed = y − f(x−35)`
- `score = (|resid_declared| − |resid_debuffed|) / (1.4826·MAD(OLS residuals))`
- `POSSIBLE_BUFF` when the score ≥ 1,5σ and `|resid_declared|` ≥ 2σ; `NORMAL` within 2,5σ; otherwise `INCONCLUSIVE`.

The +35% total MATK effect observed in the owner pair (≈24,39%) is **not** applied as a 1,35× multiplier; the model uses the curve estimated from the database.

## Assumptions / open questions

1. Equipment/Base MATK/PATK flat are not captured; adding them (form + OCR) would materially improve the model. Equipment PDEF/MDEF flat are also not stored (only the derived RPDEF/RMDEF).
2. The +35 p.p. displacement is assumed for MATK% only; PATK is the control and is assumed unbuffed (to be confirmed in-game).
3. Latest validated value per field is used; a member's fields can theoretically come from different validated submissions (the rank engine uses the same latest-per-stat semantics). The wizard submits all four together, so this is unlikely.
4. The reference pair is a single observation; the 24,39% total-MATK effect is not generalized.
