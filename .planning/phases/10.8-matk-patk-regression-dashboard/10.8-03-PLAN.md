# Phase 10.8 Plan 03 — Member-History Buff Detection (investigation fix)

**Requirements:** MREG-06
**Depends on:** 10.5/10.7 (anti-cheat panel), 10.8 (regression dashboard)
**Migration:** `0053_member_history_buff_detection.sql`

## Why

The owner seeded a buffed batch and the panel did not flag it. Investigation (live, 2026-10-31):

- The batch is **pending**, so the regression dashboard (validated-only by design) never shows it. Pending rows are reviewed in Validações.
- Ahrya / High Priest-suporte is in a cohort with only **3 real members**, below the `n >= 5` curve/σ gate — so neither `defense_spikes` nor `curve_deviations` had a baseline (`sample_size 2` / unavailable). The buffed percentages (+35 p.p. MATK%/PATK%, +95 p.p. PDEF%/MDEF%) had no reference.
- PaiDeMenina / Bard-suporte (Artista cohort, n=8) **was** flagged on `equip_mdef_pct` (4.23σ vs median 16.55, MAD 1.45). The PATK%/MATK% seed values sit inside the Artista cohort's natural spread (PATK% median 81.9, MAD 9.82; base z −1.52), so the population curve did not flag them.
- The seed changed the equipment **percentages** by the buff amounts but left `rpdef`/`rmdef` unchanged; the Angelus/Assumptio defense curve (rpdef/rmdef × 1.95) therefore could not see the flat-defense signature.

## Fix

Add a second, independent reference that works in small cohorts: the member's **own validated history**.

- `member_history_deviations(p_submission, p_member)` compares the pending buff-sensitive stats with the latest validated value (and the last 10 histories for median/MAD).
- Known signatures:
  - Impositio: `equip_matk_pct`/`equip_patk_pct` +25..45 p.p.
  - Angelus/Assumptio: `equip_pdef_pct`/`equip_mdef_pct` +80..110 p.p., or `rpdef`/`rmdef` ×1.6..2.3.
  - Generic history jump: robust z ≥ 3.5, ≥20 p.p. on a percent, or ≥25% on a flat.
- `submission_anti_cheat` gains `history_deviations`; `flagged` includes it.
- AntiCheatPanel renders "Desvio vs. histórico validado" with the previous→current values, delta in p.p./%, sample size and pattern badge.
- The regression dashboard gains a note that pending submissions are reviewed in Validações.

## Success criteria

1. Ahrya's seeded pending row is flagged by the history reference (MATK% +35.16 p.p., PATK% +35.16 p.p., PDEF% +95 p.p., MDEF% +95 p.p.; MATK +22.51%, PATK +29.73%) even though her cohort n=3.
2. PaiDeMenina remains flagged by the MDEF% sigma; with no previous validated row, the history array is correctly empty.
3. The panel shows the history evidence and the collapsed row still uses `flagged`.
4. No auto-rejection, no source-data writes, no client-executable helper.
