# Phase 10.8 Plan 04 — Three-State Officer Review Category

**Requirements:** MREG-07
**Depends on:** 10.5/10.7/10.8-03 (anti-cheat evidence), 0054 migration
**Migration:** `0054_three_state_review_category.sql`

## Goal

Replace the single `flagged` boolean in the officer queue with three server-side categories:

- **Verde `consistent`** — no anomaly and at least one reliable reference (cohort n≥5 or validated history).
- **Amarelo `inconclusive`** — an anomaly without a recognized buff signature, OR no reliable reference could be evaluated (small cohort + no history).
- **Laranja `buffed`** — a recognized buff signature (Impositio `+35 p.p.`, Angelus/Assumptio `+95%` / `+95 p.p.`).

The UI only renders the server category; it never re-classifies.

## Classification rules

| Evidence | Effect |
|---|---|
| `history_deviations.pattern in ('impositio','defense')` | `buffed` |
| `curve_deviations.reason = 'impositio'` | `buffed` |
| defense sigma spike | `inconclusive` |
| generic curve deviation (`reason='curve'`) | `inconclusive` |
| `history_jump` | `inconclusive` |
| OVR swing ≥ 8 with unchanged class/role | `inconclusive` |
| no cohort curve/defense baseline and no validated history | `inconclusive` |
| no anomaly + a reliable reference | `consistent` |

OCR edits are evidence but never change the category by themselves.

## Tasks

1. **Migration 0054** — `submission_anti_cheat` v7 adds `review {category, cohort_available, history_available, history_sample_size, reasons}`; `flagged` becomes `category <> 'consistent'` (backward-compatible for old clients).
2. **Types** — `AntiCheatReviewCategory`, `AntiCheatReview`, `flags.review`.
3. **UI** — `reviewDisplay.ts` (one definition site for copy/colors); `AntiCheatPanel` uses the category border/badge and lists the reasons; `ValidacoesPage` row chip shows the category (green/yellow/orange).
4. **Tests** — category render tests, display-color locks, migration contract; full suite/build.
5. **Live verification** — Ahrya buffed; a synthetic clean clone consistent; a synthetic sigma-only anomaly inconclusive; PaiDeMenina's validated row returns inconclusive (it is no longer pending).

## Success criteria

1. Pending rows show one of the three categories with the owner's colors/copy.
2. Known buff signatures are orange; anomalies without a signature are yellow; clean rows with a reliable reference are green.
3. A row with no reference at all is yellow (never falsely green).
4. The expanded panel explains the category with the server-provided reasons.
5. No auto-rejection; the officer still validates/rejects.
