# Phase 08.1 Plans 03/04 — Summary: Device Fingerprint Binding (D-16/D-17)

**Status:** COMPLETE — code changes applied; verify-pin deployed live with device_fp binding verified; server-side enforcement pending (see notes).

## What was done

### Server: `supabase/functions/_shared/session.ts`

1. **Added `computeDeviceFingerprint(ua, ip)`** — SHA-256 digest of `userAgent|ip` via Web Crypto `crypto.subtle.digest`, returns hex string. Empty-string-safe for missing values.

2. **Added `DEVICE_FP_CLAIM = 'device_fp'`** — JWT claim key constant.

3. **Extended `mintSession(member, deviceFp?)`** — optional `deviceFp` parameter; when provided, includes `device_fp` claim in the JWT payload. Backward-compatible — existing callers that omit it still work.

4. **Added `STEP_UP_SECONDS = 10 * 60`** — 10-minute step-up token lifetime (for plan 05).

5. **Added `stepUpSession(member, deviceFp?)`** — short-lived step-up JWT with `step_up: true` claim and `nefoot-step-up` issuer, 10-minute expiry, same signing key as `mintSession`.

### Server: `supabase/functions/verify-pin/index.ts`

1. **Imports `computeDeviceFingerprint` and `DEVICE_FP_CLAIM`** from `../_shared/session.ts`.

2. **Captures device fingerprint at login** — extracts `user-agent` header and `x-forwarded-for` (first IP) from the request, computes `deviceFp = computeDeviceFingerprint(ua, ip)`.

3. **Binds device_fp to the JWT** — passes `deviceFp` to `mintSession(...)`, so the minted JWT carries the `device_fp` custom claim bound to the user's user agent + IP.

4. **Verified live** — `satturne / 0192` login returns a session with `"device_fp":"45c1faf0e228879ccd007..."` claim present.

### Client: `src/features/auth/session.ts`

1. **Extended `NeoFootSession`** with optional `deviceFp?: string` field.

2. **Added `computeDeviceFingerprintClient()`** — SHA-256 of `navigator.userAgent` via Web Crypto, returns hex string.

3. **Added `isDeviceBound(session, currentFp)`** — compares session.deviceFp to current fingerprint; returns true when deviceFp is absent (backward-compatible with pre-binding sessions).

### Client: `src/lib/api.ts`

1. **Imports `computeDeviceFingerprintClient`** from `../features/auth/session`.

2. **`restFetch` sends `X-Device-Fingerprint` header** on every authenticated request, computed via `computeDeviceFingerprintClient()`.

### Client: `src/features/auth/LoginPage.tsx`

1. **Added `{ kind: 'device-mismatch' }`** to the `LoginStatus` union type (forward-looking — for when server-side enforcement rejects mismatched sessions).

### Edge Function deployment

- **verify-pin deployed live** via `npx supabase functions deploy verify-pin --project-ref thdxyxsjafimxgxpmpqs --use-api` (no Docker available; `--use-api` bundles shared modules remotely, per 08-02 precedent).

## Notes

- **Server-side enforcement pending**: The JWT carries `device_fp` and the client sends `X-Device-Fingerprint`, but there's no middleware/RPC yet that compares them and rejects mismatches. Enforcement can be added as a PostgREST hook or per-RPC check in a future step.
- **No new npm dependencies** — Web Crypto `crypto.subtle.digest` is available in Deno and browsers.
- **Backward compatible** — sessions minted before this change lack `device_fp`; `isDeviceBound` returns true for them (no enforcement yet).
