<objective>
Make session device binding real: one fingerprint algorithm on both sides, bound at login, and enforced server-side on the privilege-mutating staff RPCs.

Purpose: D-17 claims the session JWT is bound to a device fingerprint and "invalidated on binding mismatch". Today the server binds `SHA-256(user-agent|ip)` (verify-pin) while the client sends `SHA-256(user-agent)` (`src/features/auth/session.ts`), and NOTHING checks the header — `isDeviceBound()` is dead code. A stolen 7-day token is therefore fully usable from any machine, and the claim in CONTEXT/ROADMAP is false. A client can never learn its own public IP, so the fix is to drop IP from the server side (IP also changes on mobile networks, which would log legitimate users out).

Output: `_shared/device.ts`, verify-pin/setup-pin binding the UA-only fingerprint, migration 0024 enforcing it on the four staff RPCs, and client handling of `device_mismatch`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stolen JWT -> PostgREST | A leaked 7-day token is presented from an attacker-controlled client |
| Client -> server fingerprint | The client supplies `X-Device-Fingerprint`; the server must compare it to the minted claim |
| Edge Function -> Postgres | SECURITY DEFINER RPCs run with elevated rights; the guard must execute before any gate |
