<objective>
Remove every production credential from the smoke harness and replace it with env-supplied or per-run fixture credentials, then add a repo gate that fails if a credential reappears.

Purpose: `scripts/smoke-rls.mjs` hardcodes the owner handle `satturne` and the owner's real PIN `0192`; `smoke-rank.mjs` / `smoke-promotion.mjs` hardcode `officer-handle`; six more scripts share the literal PIN `1234` for fixtures they create. That is a committed credential set in a private-but-shared repo (WR-06, D-09/D-11/D-12). Rotation alone does not fix it — the next rotation would leak the same way. The harness must stop containing secrets at all.

Output: `scripts/smoke-config.mjs` (+ tests), `scripts/check-credentials.mjs`, and all seven smoke scripts migrated. Live execution of the migrated harness is 08.1-10's job (this plan proves the harness statically and by unit test).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repo (git history + GitHub) -> attacker | Anyone with read access to the private repo, or anyone who obtains a clone, reads committed hashes/handles |
| Smoke harness -> live database | The harness holds a Management API token and can write members/attempts rows |
| Operator shell -> `.env` | Secrets live only in the local env file; scripts must never echo or persist them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-081-09-01 | Information Disclosure | `scripts/smoke-rls.mjs` | mitigate | Live owner handle + PIN literals removed; owner credentials come from `SMOKE_OWNER_*` env only (task 3) |
| T-081-09-02 | Information Disclosure | fixture PIN `1234` across six scripts | mitigate | Per-run random 4-digit `FIXTURE_PIN` (task 1/2) — a leaked fixture hash is valid for one run and only for `smoke_*` rows |
| T-081-09-03 | Tampering | smoke matrix silently passing as a dead/wrong-role fixture | mitigate | `assertFixtureRole()` decodes the minted JWT claims and fails the run when the role is not what the matrix assumes |
| T-081-09-04 | Elevation of Privilege | harness creates rows with staff roles | mitigate | Fixtures are `smoke_*`-prefixed throwaway rows, deleted in `finally`; unique per-run handles prevent 409 residue; 08.1-06's CHECK blocks sentinel-shaped staff rows independently |
| T-081-09-05 | Repudiation | credential re-introduced later | mitigate | `scripts/check-credentials.mjs` is a permanent repo gate, re-run by 08.1-10's battery |
| T-081-09-06 | Information Disclosure | Management API token printed by a script | accept | Existing convention already forbids echoing it; scripts print only `anon key present (len=NNN)`-style facts |
</threat_model>
