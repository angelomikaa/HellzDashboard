<objective>
Harden the public hosting surface and make the deployment verifiable: ship security headers from `vercel.json` and add a one-command production release gate that proves the deployed bundle still has its Supabase env, leaks no secret, and that the auth functions are reachable.

Purpose: the 2026-10-22 outage was a build-time env regression (the deployed bundle shipped with `Missing VITE_SUPABASE_URL` and zero `*.supabase.co` URLs, so login could not reach verify-pin). Nothing in the repo detected it. This plan makes that class of regression impossible to ship silently and closes the missing-header gap on a public URL.

Output: `vercel.json` with headers, `scripts/check-deployment.mjs`, `npm run verify:deploy`, and a live PASS recorded in the plan summary.
</objective>

        }

    }

    Rules that must hold:
    - The CSP ships as `Content-Security-Policy-Report-Only` in this plan. Enforcement (renaming the header) happens only after the owner walk in 08.1-10 reports zero console violations — Tailwind's injected styles and Tesseract's blob worker are the two known risk points.

    - `img-src` must keep `data:` and `blob:` (OCR previews, card photo object URLs) and the Supabase origin (class portraits / storage reads).
    - Do NOT add `Strict-Transport-Security` here — Vercel already sends `max-age=63072000; includeSubDomains; preload` (verified live); duplicating it risks a conflicting value.

    1. **HTML fetch** — GET `/` must return 200 and its body must contain `<div id="root">`.
    2. **Header assertions** — the same response must carry, case-insensitively: `x-content-type-options: nosniff`, `x-frame-options: DENY`, a `referrer-policy`, a `permissions-policy`, a `content-security-policy-report-only` containing `frame-ancestors 'none'`, and `strict-transport-security`.

       - body does NOT include `service_role`, `sbp_`, `NEFOOT_JWT_SECRET`, or `SUPABASE_SERVICE_ROLE_KEY`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet -> Vercel edge | Untrusted browsers fetch HTML/JS; headers decide what the page may load and who may frame it |
| Internet -> Supabase functions gateway | Untrusted callers reach verify-pin/step-up with only the public anon key |
| Build pipeline -> bundle | Build-time env decides whether the shipped client can reach Supabase at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-081-07-01 | Information Disclosure | deployed JS bundle | mitigate | Gate step 3 asserts the bundle contains no `service_role` / `sbp_` / `NEFOOT_JWT_SECRET` string on every release |
| T-081-07-02 | Tampering | Vercel build env | mitigate | Gate step 3 fails when `Missing VITE_SUPABASE_URL` is present or the project ref is absent — the exact 2026-10-22 regression |
| T-081-07-03 | Spoofing | clickjacking of the login page | mitigate | `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'` |
| T-081-07-04 | Information Disclosure | referrer leakage of session-bearing URLs | mitigate | `Referrer-Policy: strict-origin-when-cross-origin` (sessions live in localStorage, never the URL, so this is defense in depth) |
| T-081-07-05 | Denial of Service | undeployed Edge Function | mitigate | Gate step 4 treats a 404 from verify-pin/step-up as a release failure |
| T-081-07-06 | Elevation of Privilege | CSP bypass via inline script | accept | CSP ships report-only this plan; `script-src 'self'` is already the enforced direction once 08.1-10 clears the owner walk |
</threat_model>
