# Phase 08.1: Server-enforced session device binding

**Device binding stops being theater: the same UA-only fingerprint is minted into the JWT `device_fp` claim at login and first access, sent as `X-Device-Fingerprint` on every API request, and enforced by `assert_device_bound()` as the first statement of all four staff RPCs. A device-mismatched session is discarded client-side and the user lands on login.**
