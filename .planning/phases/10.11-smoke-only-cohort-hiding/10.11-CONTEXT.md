# Phase 10.11 — Smoke-Only Cohort Hiding (CONTEXT)

**Inserted:** 2026-11-01 (owner request; migration 0055 + client)
**Scope:** Início showcase only.

## Owner request

> "vamos ocultar as coortes que até o momento estão compostas apenas por smokes — por exemplo, as duas de algoz. As builds são viáveis, a guilda apenas não tem nenhum jogador na classe nesse momento. Se algum jogador mudar para algoz, a coorte deve voltar aos destaques imediatamente"

## Why a server flag

Before 0055 the Início payload had no way to tell a smoke fixture from a real
member: cards carry only `display_name/ovr/photo_path/highlights`. Detecting
`display_name like 'Smoke %'` on the client would be a name heuristic (a real
member could rename themselves into or out of it) and would duplicate the
fixture namespace rule that already lives in SQL.

Migration 0055 adds one additive boolean per card:

```
'placeholder', coalesce(m.discord_handle like 'smoke%', false)
```

`smoke%` is the sanctioned fixture namespace already excluded by every other
RPC (posts, inspector, regression, lineups). No real member can hold it.

## Decisions

| Decision | Choice |
|---|---|
| Granularity | **Per build** (`class_name` + `char_function`) |
| Hide rule | Drop the build when **all** its cards are placeholders |
| Keep rule | A build with at least one real card renders; placeholders stay as fillers (Mastersmith: Synyster + 2 primers) |
| Return rule | Compute-on-read: the build reappears as soon as one real member has data — no re-seed, no manual flag, no cache |
| Deploy order | Migration first (done), client bundle second |
| Fallback (10.10) | Still applies, but now only to real-member builds with no platinum card |

## Constraints

- Additive field only; highlights' closed field list untouched.
- No client rank math; server order preserved.
- An older server payload without the flag is treated as real (deploy-order safety).
