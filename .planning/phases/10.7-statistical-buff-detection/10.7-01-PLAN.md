# Phase 10.7 Plan 01 — Statistical Buff Detection

**Requirements:** CURVE-01, CURVE-02, CURVE-03, CURVE-04
**Depends on:** Phase 10.5 (anti-cheat panel), Phase 10.6 (stat inspector), Phase 10.1 (OVR formula untouched)
**Migration:** `0049_statistical_buff_detection.sql`

## Goal

Replace the fixed-margin-only judgement with a data-driven model: fit the flat/percent curve per stats cohort, test the Impositio Manus undo transform, and add a robust σ signal to both the officer queue and the cross-cohort inspector. The 1.5× rule stays as the fallback for small cohorts.

## Tasks

1. **Migration 0049**
   - `curve_deviation(p_submission, class, function, flat_key, pct_key)` — internal helper: normalized base over the cohort, median/MAD, expected flat, sigma, curve deviation, Impositio undo test. `n ≥ 5`; otherwise `available:false`.
   - `submission_anti_cheat` v4 — defense spikes gain median/MAD/z/reason and a σ ≥ 3.5 path; new `curve_deviations` for `patk/equip_patk_pct` and `matk/equip_matk_pct`; `flagged` includes curves.
   - `stat_overview` v3 — `class_median`, `class_mad`, `class_z`, `class_sigma_outlier` per row; direction-aware sigma; the 1.5× fields stay.
   - Grants/comments/bookkeeping + pgrst reload.
   - Same-session correction: all `percentile_cont` results cast to `numeric` before `round` (Postgres has no `round(double, int)`); 0049 re-applied after the fix.

2. **Client API**
   - `AntiCheatDefenseSpike` gains optional `median`/`mad`/`z`/`reason`.
   - New `AntiCheatCurveDeviation`; `AntiCheatFlags.curve_deviations`.
   - `StatOverviewRow` gains `class_median`/`class_mad`/`class_z`/`class_sigma_outlier`.

3. **Officer panel**
   - Spike rows show median and σ.
   - New "Curva de atributos (ATK/MATK)" block: Impositio verdict with expected flat, observed pct/base, and the de-buffed base; general curve deviation; unavailable note for n < 5.

4. **Ranking inspector**
   - Cohort cell shows `média · mediana (n)`; new `Nσ` column; `σ ≥ 3.5` badge "Fora da curva (Nσ)" takes priority over the 1.5× and guild badges.
   - Note copy explains all three signals.

5. **Tests**
   - `statisticalBuffDetectionMigration.test.ts` (static locks).
   - Panel render tests for Impositio, unavailable curves, and the clean state.
   - `rankView.test.ts` helper updated for the new fields.
   - Full suite, `tsc -b`, `oxlint`, `vite build`.

## Success criteria

1. A synthetic Impositio submission (`patk×1.35`, `equip_patk_pct+35`, same for MATK) is flagged `reason='impositio'` on both curves; a normal clone and a legitimate high-% build are not (CURVE-01/02).
2. A flat-only inflation (`patk×1.8`, pct unchanged) is flagged `reason='curve'` (CURVE-01).
3. A defense value at 3.7σ but 1.21× the average is flagged `reason='sigma'` (CURVE-03).
4. The inspector flags the same 3.7σ value with `class_sigma_outlier:true` while `cohort_outlier:false` (CURVE-03).
5. Small cohorts (n < 5) return `available:false` / null sigma and never produce a curve/sigma flag; the 1.5× rule still applies (CURVE-04).
6. No auto-rejection, no key-stat leak, no client-executable internal helper, no new dependencies.
