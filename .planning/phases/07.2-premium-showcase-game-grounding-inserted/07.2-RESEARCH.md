## 2. Architecture Patterns (verified against code)

### 2.1 RPC gate pattern (every new RPC copies this)

```sql
-- Internal gate FIRST — member_role claim + live active flag (0009:62-68 shape):
if coalesce(auth.jwt()->>'member_role', '') not in ('officer', 'owner')
   or not exists (select 1 from members m
                 where m.id::text = auth.jwt()->>'member_id' and m.active) then
  raise exception 'forbidden';
end if;
```

- Member-invocable RPCs use the member gate instead (0011:302-309 shape): `member_id` claim + active check.
- `security definer` + `set search_path = public` + `stable` (read-only) on every report function.
- EXECUTE hygiene (0009:338-345, WR-02): `revoke execute ... from public, anon; grant execute ... to authenticated;` for EVERY function.
- `comment on function` states the gate + exception tokens (house comment discipline).

## 3. Server Design (planner/researcher territory per CONTEXT discretion)

### 3.1 Relevant tier (RELV-01, D-04/D-05/D-06)

**Storage:** `class_relevant_stats (class_name text, stat_key text, PK(class_name, stat_key))` with FKs mirroring `class_key_stats`. Separate table (not a tier column on `class_key_stats`) because `class_key_stats` is load-bearing for OVR in 0009/0011 RPCs and dozens of probes; a side table is additive-only.

**RLS:** deny-all by default; staff-only select policy copying `staff_select_key_stats` (0009:32-37). All writes through RPCs.

**`set_relevant_stat(p_class, p_stat_key, p_enabled)` — staff-only, implements D-05 exactly:**
- Takes `pg_advisory_xact_lock(hashtext('cks:' || p_class))` — the SAME lock key as `set_key_stat` (0009:77) — so key and relevant toggles for one class serialize against each other.
- `p_enabled = true`: reject `'forbidden'` if key count ≠ 6 for the class (rule 2: relevant only after the key set is complete); reject `'already_key'` if the stat is currently key (rule 1: key XOR relevant); insert `on conflict do nothing`.
- `p_enabled = false`: delete the row (rule 3: removing a KEY never touches relevant rows — but this RPC only removes relevant rows).
- Returns the class's current relevant count.

**`set_key_stat` supersession (rule 4 — promotion demotes):** `create or replace` in 0013 with exactly one behavioral addition: after a successful key insert, `delete from class_relevant_stats where class_name = p_class and stat_key = p_stat_key` ("a relevant stat becomes key when selected"). Deselecting a key (p_enabled=false) makes NO relevant change (rule 3). All existing exception tokens preserved (`forbidden`/`key_stat_limit`/`unknown_class`) — smoke-rank must stay green.

**Phase 9 forward-compatibility (D-23):** the governance RPCs and all card/foco reads query whatever key config exists at runtime (`class_key_stats` today; the RPC bodies and client read paths never hardcode the config's cohort shape beyond the class_name key that survives Phase 9's re-keying). The relevant table gets the same class_name key shape so Phase 9 re-keying migrates both tables identically.

### 3.2 Member card payload (CARD-01, D-03/D-13/D-23)

**New RPC `my_card()`** — member-invocable, dedicated sanctioned surface. `my_report()` stays BYTE-IDENTICAL (all existing leak probes keep passing untouched; the sanctioned reveal lives in the NEW contract):

```json
{
  "char_class": "...", "char_function": "dps|mdps|suporte",
  "ovr": { "value": 77.2 | null, "data_sufficient": bool },
  "key_stats": [   // exactly the class's key stats at runtime (≤6; D-23 reads live config)
    { "stat_key": "...", "label": "...", "label_short": "CRC",
      "value_type": "flat|percentual", "own_value": num|null, "points": num|null }
  ],
  "relevant_stat_keys": ["...", "..."]   // identity only — guides foco (D-07)
}
```

Leak-safety proof points: NO weights/toggles/config fields; NO class_average/best on key_stats (D-02: cards show no aggregates); key identity = only what the cards legitimately display (D-03 sanctioned reveal). `ovr`/`points` reuse the 0009 formulas verbatim (copy the CTEs). When the class has no key config, `key_stats` is `[]` and `ovr.value` is null (the 04 D-12 incomplete-config semantics).

**`get_promotion` supersession (D-13):** `create or replace` — the `hl` lateral's top-6-by-points subselect becomes the class's key stats (join `class_key_stats` on the card's class, order by `sc.label` for stable order), same closed fields `{stat_key, label, value_type, value, points}` + add `label_short`. Everything else (top-5-by-OVR, D-07 active cohorts, omitted classes) byte-preserved. Comment updated: highlight selection is now the sanctioned key reveal per 07.2 D-13 (RNK-02 re-baselined; config still never serialised).

### 3.3 Officials rank view (RANK-02, D-18/D-19/D-20)

**New RPC `role_rank(p_function text, p_class text DEFAULT NULL)`** — staff-only gate. Returns one row per active member whose `char_function = p_function` (optionally filtered to `p_class`), **ranked by OVR within the role** (cross-role comparable currency per D-18), OVR computed with the exact class_top5/my_report lateral (each member still ranks inside their own class+function cohort — the OVR is the cross-role sort key, not a re-cohorting):

```json
[ { "member_id", "display_name", "char_class", "char_function", "ovr": num|null,
    "stats": [ 57 × { "stat_key", "label", "label_short", "value_type",
                      "value": num|null, "points": num|null, "class_average": num|null } ] } ]
```

- `p_function` whitelist raises `invalid_function` before other checks (05-02 assertion-shape lesson: pin the actual contract token first).
- `p_class = NULL` (or `''`) = all classes (default board state).
- Order: `ovr desc nulls last, display_name` — server order, client renders verbatim.
- Heavy payload (57 × ~70 members) is acceptable: staff-only, guild-scale, single fetch per board switch.
- Members NEVER reach it: staff gate inside the RPC (D-20 — not tab-hiding only).

### 3.4 Foco rule (D-07) — client-side pure function

`improvementFocus(stats: MyReportStat[], priorityKeys: Set<string>, lowerIsBetter: Set<string>): MyReportStat[]` in presentation.ts (replaces `focusCandidates`):

1. Eligible = `points !== null` AND `stat_key ∈ priorityKeys` (key ∪ relevant, from `my_card`).
2. **Behindness** (scale-free, handles flat vs percentual): `gap = own_value − class_average` for higher-is-better; `class_average − own_value` for the three lower-is-better stats (`fixed_ct_pct`, `global_cd_pct`, `variable_ct_pct` — a lower-than-average negative stat is BETTER). Normalize: `gap / |class_average|` when `|class_average| ≥ 1e-9`, else raw `gap` (unnormalizable near-zero averages; documented fallback).
3. Keep `behindness < 0` (behind average) first; if fewer than 3 candidates are behind, fill with the smallest-positive-gap ones (strip still shows 3 when 3 are eligible).
4. Sort: most-behind first, stable tie-break by catalog order (existing strip rhythm).
5. Strip items keep the points chip (points arrive in MyReportStat already).

Pure + TDD-able (10-12 cases: behind/in-front/lower-is-better/near-zero-average/ties/fewer-than-3/none-eligible).

## 7. Common Pitfalls (from project history)

1. **42P17 recursion** — never inline exists-subquery-on-members in a policy guarded by members policies; use the RPC-internal gate (0008 lesson).
2. **Advisory lock race** — key/relevant toggles share `hashtext('cks:'||p_class)` or two officers can violate D-05 concurrently (0009 CR-01 lesson).
3. **`create or replace` must be a FULL body copy** of the superseded function plus the minimal change — paraphrasing drifted rank math once already (0011 header lesson).
4. **PostgREST 204 ambiguity** — probes assert zero-row bodies via `Prefer return=representation`, never bare status codes (05-02 lesson).
5. **EXECUTE defaults to PUBLIC** — every new function needs the revoke/grant pair (WR-02).
6. **Smoke residue** — cleanup removes members, submissions, submission_stats, key/relevant rows, and pin_login_attempts; second consecutive run must be identically green (03/06 discipline).
7. **Canvas taint** — any http(s) cross-origin image silently kills `toBlob`; self-hosted same-origin only (D-15 rationale).
8. **Font not loaded when canvas draws** — first export renders fallback font unless `document.fonts.load` is awaited.
9. **Tailwind v4 JIT** — literal class names only; new yellow token must appear verbatim in a map or utility.
10. **Preview staleness** — any preview-based UAT runs `npm run build` immediately before `npm run preview` (06 lesson).
11. **Composite React keys** — display_name has no unique constraint; rank table keys use member_id (returned by role_rank).
12. **my_report byte-stability** — do NOT extend my_report for card data; the new surface is my_card (keeps every existing leak probe green untouched).
