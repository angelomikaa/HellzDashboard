# Phase 07.1 Plan 01: Hellz Visual Identity Token Layer + Display Font Summary

**One-liner:** Logo-red accent ramp (#DC3538 family) on logo-anchored near-black surfaces with red-tinted hairlines, plus self-hosted Orbitron woff2 (600/700/900) with preloads and static glow/grid utilities — the contract layer plan 02 styles against.

## What Was Built

- **Task 1 — Orbitron woff2 subsets:** Three distinct Google Fonts static latin subsets (6,588 / 6,528 / 6,400 bytes) committed to `public/fonts/`. Validated beyond the plan's gate: wOF2 magic bytes, header-declared length == actual, pairwise byte-distinct, and fonttools-parsed cmap with **zero missing pt-BR diacritics** (ç ã õ é ê í ó ú à â – —; 183 glyphs each). SIL OFL 1.1, no CDN, no npm dependency.

Three `@font-face` blocks (`font-display: swap`) pointing at `/fonts/orbitron-latin-*.woff2`; `--font-display: "Orbitron", "Segoe UI", system-ui, sans-serif`. Custom utilities `glow-accent`, `glow-text-current` (currentColor → tier-colored glow for free), `backdrop-neon-grid` (D-04 scope enforced by consumers). `h1` base rule inherits the display font. `prefers-reduced-motion: reduce` transition kill-switch. Three `rel="preload" as="font"` links in `index.html`.
- **Task 3 — Legacy palette eradication:** `SubmitPage.tsx:94` `accent-[#E3B341]` → `accent-accent` (its `focus-visible:ring-accent` now resolves to red automatically). `FocusStrip.tsx:10` comment updated to reference interaction red `#DC3538`. ## Deviations from Plan

**1. [Rule 3 - Blocking issue] Font size gate lower bound (8 KB) too tight for actual subsets**
- **Found during:** task 1
- **Issue:** Google's static latin subsets of Orbitron weigh 6,400–6,588 bytes — below the plan's estimated 8–60 KB bound. The gate's intent (valid woff2, not an HTML error page / not a byte-identical dummy) is fully satisfied.
- **Fix:** Replaced the size check with stronger validation: wOF2 magic, header-declared length == actual file length, pairwise byte-distinctness across weights, and fonttools cmap parse confirming all required pt-BR codepoints present.
- **Also:** the plan's primary fetch path (modern Chrome UA) returned the same **variable-font** URL for all three weights — which would have recreated the removed byte-identical-dummy situation. Used a pre-variable-font-support UA (Chrome/60) so Google served genuinely distinct static instances per weight, matching the environment note's "different byte sizes per weight" expectation.
- **Files modified:** none beyond plan (3 woff2 files as planned)
- **Commit:** fcd9c2e

No other deviations — plan executed exactly as written otherwise.
