# Phase 07.1: Visual ID implementation - Context

**Gathered:** 2026-10-15
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 07.1 (urgent insertion) applies the Hellz visual identity across the panel: the h-logo mark (sharp, modern, red neon, dark, city, futuristic — sci-fi look) becomes the product's visual system. This covers: (a) the **accent system** — logo-red replaces the gold UI accent everywhere; (b) the **surface palette** — shift from GitHub-dark to the logo-anchored near-black + red-tinted hairlines; (c) **moderate neon treatment** — glows on key moments only; (d) **logo placement** — favicon, login hero with lockup, compact header mark; (e) **typography** — one display font for hero elements. Implementation stays within the existing Tailwind v4 `@theme` token architecture, pt-BR copy, mobile-first constraints. No functional behavior changes, no rank/display logic changes, no new tabs or pages.

**Requirements covered:** none from REQUIREMENTS.md (visual identity was inserted as urgent work; roadmap entry TBD). Success criteria will be defined at planning from the decisions below.

**Not in this phase:** light theme (single dark theme only), animated/pulsing glows, scanline noise textures on every page, custom body font, re-theming the tier band VALUES (bronze/silver/gold/platinum colors stay semantically distinct — see D-02), per-role color signals, any Destaques/dashboard layout restructuring (pure restyle), PWA manifest/icons beyond favicon (deferred).

</domain>

<decisions>
## Implementation Decisions

### Accent system
- **D-01: FULL RED SWAP.** The logo red family (#b70302 / #b3080a, brightened as needed for WCAG contrast on the dark surfaces) becomes THE interactive accent: focus-visible rings, active tab indicator, primary buttons, links, interactive highlights. The gold `--color-accent: #E3B341` is retired from UI chrome. Gold survives ONLY as the `--color-tier-gold` card token (different context: tier badges on stat cards vs UI controls — no collision). Single dominant neon accent, fut.gg-style.
- **D-02:** Tier tokens (bronze/silver/gold/platinum) keep their semantic identity — they may be subtly tuned for contrast on the new surfaces but must remain instantly distinguishable from the brand red and from each other. If tier-gold reads too close to any retained warm accent, tier-gold wins the warm slot and the UI accent stays red.

### Surfaces & mood
- **D-03: LOGO-ANCHORED DARK.** Surfaces shift from the current GitHub-dark pair (#0D1117/#161B22) toward the logo's near-black family (#1a1a1a anchors) with **red-tinted hairlines/borders** (e.g., dark red-gray line color instead of #30363D neutral). The 60/30/10 surface discipline (dominant/surface/line) in `@theme` is preserved — only the values change. Text colors (content/muted) re-tuned for contrast on the new surfaces if needed.

### Neon intensity (moderate — the fut.gg register)
- **D-04:** Neon treatment is **moderate and static**: glow (box/text shadow) reserved for key moments — active tab indicator, OvrHero OVR number, Destaques tier accents, login hero, focus rings. A subtle grid/gradient sci-fi backdrop is allowed on **login and Destaques only** — not on data-dense pages (Painel, Enviar, staff pages stay clean for readability).
- **D-05:** **Static glows only — no animated pulses, no looping animations** (mobile performance, battery, readability). Hover/focus transitions may brighten a glow but nothing auto-animates. `prefers-reduced-motion` respected for any transition added.

### Logo placement
- **D-06: FULL SET.** `h-logo/hellz.svg` (the shipped mark — recolor if needed for dark-surface contrast) appears as: (1) **favicon** replacing the default Vite icon in `index.html`; (2) **login hero** — large mark + "Hellz — Painel Geral" lockup; (3) **compact mark in the app header** left of "Olá, {name}". No logo inside the tab bar or on cards.

### Typography
- **D-07: DISPLAY FONT FOR HERO ELEMENTS.** One display font from the geometric/technical class (Orbitron/Rajdhani-like) for: the wordmark/lockup, page headings, and the OVR/points hero numbers. Body text, labels, and forms stay on the current system stack. Font ships as a subset woff2 via `@font-face` (self-hosted in the repo, no CDN), with system-font fallback so nothing breaks if it fails to load. pt-BR diacritics must be covered by the subset.

### Design north star (owner verbatim)
- **D-08:** https://www.fut.gg/players/ and especially the player dashboard https://www.fut.gg/players/37576-ronaldo/27-37576/ are the color-usage references — "does a good use of neon colors while remaining mostly dark". Pattern to emulate: near-black base, one dominant neon accent, thin neon borders/soft glows on interactive cards, neon-gradient hero numbers, restrained motion.

### OpenCode's Discretion
- Exact hex values for the red accent ramp (brightened variants for small-size contrast, muted variants for borders) — anchored on #b70302/#b3080a, verified against WCAG AA for text/focus use
- Exact surface/line hex values within the logo-anchored brief
- Choice of the specific display font (geometric/technical class, pt-BR subset, license-safe)
- Whether hellz.svg needs an SVG recolor/light variant for dark surfaces vs using it as-is
- Glow blur radii/spreads, grid backdrop density/opacity
- Tailwind v4 `@theme` token naming for new tokens (accent ramp, glow utilities)
- Whether the tier-palette needs per-surface contrast nudges (values stay locked, colors are presentational)

</decisions>

## Existing Code Insights

### Reusable Assets
- `src/index.css` `@theme` block — the single token source; swapping accent/surface/line values propagates automatically to every `bg-dominant`/`border-line`/`text-accent`/`ring-accent` utility across all pages (grep shows token-utility usage, not hardcoded hexes)
- Tier token system (`--color-tier-*`) + `presentation.ts` band mapping — presentational layer already separated; tuning colors touches only tokens
- `h-logo/hellz.svg` — clean vector, 4 flat fills, trivially recolorable; scales from 16px favicon to hero size

- Tailwind v4 CSS-first: tokens in `@theme`, no tailwind.config — new glow/display-font utilities follow the same CSS-first approach
- pt-BR copy everywhere; mobile-first single-column; 60/30/10 surface discipline documented in token comments
- No CSS frameworks beyond Tailwind; no icon library dependency for this (logo is in-repo SVG)

### Integration Points
- `index.html` — favicon swap + display-font preload
- `App.tsx` header — compact mark insertion (before "Olá, {display_name}")
- `LoginPage` — hero restructure (mark + lockup + backdrop)
- `OvrHero` / `HighlightsPage` — glow + display-font application
- Any hardcoded legacy hexes (e.g., login panel styling) — audit and tokenize
