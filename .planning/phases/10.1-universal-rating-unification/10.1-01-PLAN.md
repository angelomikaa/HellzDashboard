# 10.1-01 — Migration 0036: one rating formula, one key set, one cohort

## Problem (proven 2026-10-27, owner report)

The Ranking tab (`role_rank`), the Painel card (`my_card`) and the Solicitações board
(`staff_requests`) still run the pre-Phase-9 rank-percentile formula and (for the latter
two) broken key-set reads, while `my_report`/`class_top5`/`get_promotion(_public)` run the
Phase 9 value-proportional formula. Live audit: **6 of 6 OVR-capable members show different
OVRs across surfaces; 3 show null on the Ranking tab while their cards show a number**
(see `10.1-CONTEXT.md` §2 for the measured table).

## Tasks

1. **role_rank rebase — value-proportional points + key filter.** Byte-faithful
   supersession of the 0024 body (gate, `invalid_function`/`unknown_class` whitelist,
   CTE structure, server ordering, payload field list unchanged) with exactly these
   changes:
   - `agg` gains `max(value) as max_v, min(value) as min_v` (keeps `n`, `avg_v` — the
     stats list still renders `class_average`);
   - the `cmp` CTE is DROPPED (rank-based below/ties counting has no consumer left);
   - the stats-lateral `points` expression becomes the 0028 `my_report` shape:
     `case when coalesce(ag.n, 0) >= 3 and lt.value is not null then
     least(greatest(round(case sc.stat_direction when 'lower' then
     lt.value / nullif(ag.min_v, 0) else lt.value / nullif(ag.max_v, 0) end * 99, 2), 0), 99) end`;
   - the OVR lateral becomes the 0029 `ovr_rows` shape over `class_key_stats ks
     join stat_catalog c` + `latest o` + `agg ag`, keyed `ks.class_name = rm.char_class
     and ks.char_function = rm.char_function and ks.selection_order <= 6`
     (the missing key filter is defect #2 in 10.1-CONTEXT §4);
   - `comment on function` updated: value-proportional (Phase 9 SCALE-01) +
     selection_order<=6 (0028 owner rule) + staff-only gate unchanged.
2. **my_card rebase — formula swap only (key filter already present from 0028).**
   Byte-faithful supersession of the 0028 body with exactly these changes:
   - `agg` gains `max(value) as max_v, min(value) as min_v`;
   - the OVR subquery's `p` expression becomes the value-proportional CASE (add the
     `stat_catalog c` join for `stat_direction`);
   - the `key_stats` points CASE becomes the same value-proportional shape via
     `c.stat_direction`;
   - payload shape (fields, order by label, closed field list) unchanged;
   - comment updated.
3. **staff_requests rebase — formula + BOTH missing filters.** Byte-faithful
   supersession of the 0014 body with exactly these changes:
   - `agg` gains `max(value) as max_v, min(value) as min_v`;
   - the OVR lateral's `p` expression becomes the value-proportional CASE with the
     applicant's own value from `membership_request_stats rq` (join `stat_catalog sc`
     for direction), and the key-set read gains BOTH missing predicates:
     `ks.char_function = r.char_function` (the 0018-era omission that nulled every
     applicant OVR) AND `ks.selection_order <= 6`;
   - cohort discipline unchanged: ACTIVE members of the applicant's class+function,
     applicant stats never join it (D-14), rank-based `below/ties` counting dropped;
   - comment updated.
4. **my_report cohort alignment — formula untouched.** Byte-faithful supersession of the
   0028 body with exactly two changes: `latest` filters
   `sub.status not in ('rejected','discarded')` (was `<> 'rejected'`) and `cohort` gains
   `and m.active`. Everything else (57-stat list, `last_validated_at`, value-proportional
   points, OVR, payload shape) byte-identical.
5. **class_top5 cohort alignment — formula untouched.** Byte-faithful supersession of the
   0028 body with exactly two changes: `latest` filters
   `sub.status not in ('rejected','discarded')` and `class_members` gains `and m.active`.
6. **Bookkeeping + reload.** `begin; ... commit;` wrapper; insert the `0036` row into
   `supabase_migrations.schema_migrations` (0012/0028/0029 pattern,
   `on conflict (version) do nothing`); final statement
   `notify pgrst, 'reload schema';` (0035 lesson: the Management API Run Query endpoint
   never emits PostgREST's reload NOTIFY, so a just-replaced RPC answers
   "no function matches" until the next DDL). Grant hygiene per body: revoke from
   public/anon, grant to authenticated (unchanged grants — no widening).

## Hard constraints

- **Append-only:** 0001–0035 are never edited. No `drop function` on any of the six
  bodies (`create or replace` only, exact signatures).
- **Zero payload-shape changes:** field lists, key ordering (`order by sc.label` /
   `c.group_name, c.label`), null semantics and error vocabulary are byte-preserved —
  the client renders these values verbatim and must not need a change.
- **get_promotion / get_promotion_public: NO `create or replace` in this file** (D-10.1-04).
- The `least(greatest(round(...)))` value-proportional expression must be copied from
  the 0028 shapes verbatim — no re-derivation, no "equivalent" rewrite.
