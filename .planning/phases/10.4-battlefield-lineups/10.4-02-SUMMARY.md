## What was built

- **API (`src/lib/api.ts`)**: `fetchLineups`, `setLineupSlot` (null clears a slot), `setLineupPartyLabel` (null clears a label). Each wrapper calls its RPC through the existing `restFetch` (both gateway headers and the device fingerprint). Responses pass through `asLineupsPayload`, which rejects a malformed payload or an unknown battlefield as `ApiError`. The types are a closed field list: display-only roster fields, no stats, OVR, key-stat config or `pin_hash`.
- **Model (`lineupModel.ts`)**: battlefield metadata (titles, Raid 1/2, file slugs), `CLASS_ACCENT_HEX` for the 15 classes plus a neutral fallback, party and battlefield counts, `isPartyFull`, assignment lookup, `filterAssignableRoster` (unassigned first, then assigned with their current raid/party badge), pt-BR error copy (`lineupErrorCopy`), and role-label normalisation (trim, blank clears, max 40).
- **Navigation (`App.tsx`)**: "Lineup" tab after "Enviar Status", visible to all roles. The page is lazy-loaded. There is no staff gate on the tab; writes are gated by the server.
- **Page (`LineupPage.tsx`)**:
  - Header with the title and the member's own assignment callout (`Você está em: Vigrid Field (Raid 1) — G7 (Slot 5)`).
  - Battlefield tabs with `N/40` counts, plus an md+ "Ver ambas" stacked mode.
  - Responsive grid (`grid-cols-1 md:grid-cols-2 lg:grid-cols-4`) of 8 party cards.
  - Each card has the role-label pill, a `G#` header with a "Sua PT" chip when it holds the viewer, five slots (class-colour bar, `ClassCrest`, `LÍDER` on slot 1, pt-BR class label, "Você" on the viewer's slot with the accent border and glow), and a green `5/5` or amber `N/5` footer.
  - Officers and owner: each slot opens an inline picker with search, a "Limpar slot" action, and the raid/party badge plus "mover" on members already seated elsewhere. Each party's role label is editable inline with the two presets, custom text (max 40) and "Limpar função".
  - Write failures show pt-BR copy and keep the last good board on screen.
- **Tests**: 25 new tests (api wrappers, payload validation, model helpers, member versus officer rendering, error copy).
