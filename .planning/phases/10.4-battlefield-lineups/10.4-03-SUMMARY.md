## What was built

- **Layout planner (`buildLineupExportPlan`, pure)**: a 1920×1080 plan.
  - Header (y 0–148): Hellz mark, `HELLZ — PAINEL GERAL` kicker, the title `VIGRID FIELD — RAID 1` or `RUINSCAPE — RAID 2`, the `N / 40 ESCALADOS` pill, and a red neon rule.
  - Role banners (y 170–206): centered over each column when `role_label` is set.
  - Eight party columns (G1–G8): 216px wide with 16px gutters and 40px margins. Each has a red header band with its `G#` label, five slot cards, and an `N/5` footer. The footer is green when full and amber otherwise.
  - Slot cards: a 6px class-colour bar, a 14% class tint, the class icon (or a monogram tile when there is no icon), the nickname, and the pt-BR class label. Slot 1 is the leader (`★ LÍDER` tag, gold border). Empty slots are dashed `— VAGO —`.
  - Legend strip (y 1012–1036): one swatch and pt-BR label per catalog class.
  - Missing parties or slots render as vacant, so the plan always has 8 columns × 5 slots.
- **Filename contract**: `hellz-lineup-vigrid-field.jpg` and `hellz-lineup-ruinscape.jpg`.
- **Canvas shell (`renderLineupCanvas`, `downloadLineupJpg`)**:
  - Waits for `Orbitron` and `Bebas Neue` before drawing.
  - Paints the full `#141414` background first, because JPEG has no alpha.
  - Fits text by shrinking to a 60% floor, then ellipsizes. Labels never spill out of their boxes.
  - Exports `image/jpeg` at quality 0.94, then triggers a download through an object URL.
- **Same-origin assets only**: the bundled `hellz-mark.svg`, and the class icons resolved by `iconSrcFor()`. `iconSrcFor` is a new named export in `ClassCrest.tsx` that uses the same manifest lookup as the grid. Nothing cross-origin is drawn, so the canvas is not tainted.
- **Page wiring (`LineupPage.tsx`)**:
  - `Baixar JPG — Vigrid Field (Raid 1)`, `Baixar JPG — Ruinscape (Raid 2)`, and `Baixar ambas (JPG)`.
  - While rendering, the active button reads `Gerando JPG…` and all three are disabled.
  - "Ambas" runs the two exports one after the other, so the browser does not block the second download.
  - A failure shows the pt-BR alert `Não foi possível gerar o JPG. Tente novamente.` (no internals).
- **Tests**: 14 new planner tests covering the 1920×1080 canvas, 8 equal non-overlapping columns, every rectangle inside the canvas, five slots per column, the leader flag on slot 1 only, class label and accent, monogram fallback for a null class, `N/5` counters and their colours, `N / 40` totals, role banners, titles, filenames, the 15-entry legend, and the missing-party fallback.

## Deviations from Plan

**1. [Rule 2 - Missing critical] Button-wiring tests were not added.** The plan lists `LineupPage.test.tsx` as a file to touch. The existing page tests use `renderToStaticMarkup`, which never runs the fetch effect, so the export buttons can't be reached that way. The repo has no DOM test setup (no jsdom or Testing Library), and adding one would break the zero-new-dependency invariant. The export logic is covered by the planner tests. The button wiring is covered only by `tsc`, the build, and review.

**2. [Rule 1 - Robustness] Missing parties and slots render as vacant instead of being dropped.** The server always returns 8 parties × 5 slots. The planner still tolerates a sparse payload, so a partial response cannot shift columns or crash the export.

Total deviations: 2 (1 test-coverage gap, 1 robustness fallback). No architectural changes.
