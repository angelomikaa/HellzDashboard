# Phase 10.9 — Ranking UI Reorganization (CONTEXT)

**Inserted:** 2026-10-31 (owner request, UI-only)
**Scope:** staff Ranking tab only — no server, migration or rank-math change.

## Owner request

The staff Ranking page had grown into two nested modes (OVR board / "Stat entre todos")
with a third view (Regressão) buried inside the second one, and the per-player 59-stat
detail expanded inline under the row, pushing the table apart. The owner asked for three
clear, sibling sections and a compact per-player detail.

## Decisions (locked at discussion)

| Decision | Choice |
|---|---|
| Structure | **Option A** — one tablist with three sibling sections: `Ranking OVR`, `Explorador de stats`, `Análise estatística`. No nested tabs. |
| Default section | `Ranking OVR` |
| Player detail | Accessible **modal** (`role="dialog"`), not an inline `<tr>` |
| Modal content | OVR + all 59 stats grouped (Geral/Quasi/Especial) + class average + points |
| Stat explorer | Searchable stat picker + class (merged cohort, e.g. Artista) and function filters |
| OVR board toolbar | Function board, class filter, sort select, name/ID search |
| OVR table | Function column removed (the board already is the function) |
| Methodology / reference pair | Collapsed `<details>` by default inside the analysis section |
| Three-state review chips | Stay in **Validações** (10.8-04); not duplicated here |

## Constraints

- Staff-only surfaces by construction (each RPC keeps its own internal gate).
- Filters are client-side view aids over already-fetched payloads — no new RPC, no
  extra round trip, no rank math on the client.
- No new npm dependencies; no key-stat config exposed.
- FLEE and PvE bonuses remain out of scope (they do not influence any OVR).
