Live census query (Management API via `scripts/apply-seed.mjs` or `mgmtQuery`):
```sql
select role, count(*) filter (where pin_hash is null) as unclaimed,
       count(*) filter (where discord_handle ilike 'dummy-%') as dummies,
       count(*) as total
from members group by role;
```
Conversion rule:
```sql
delete from pin_login_attempts
where discord_handle in (
  select discord_handle from members
  where role <> 'owner' and discord_handle not ilike 'dummy-%'
);

update members set pin_hash = null, claimed_at = null
where role <> 'owner'
  and pin_hash is not null
  and discord_handle not ilike 'dummy-%';
```
Attempt deletion is unconditional for non-owner real rows so a pre-existing lockout cannot block the first-access claim; it is also idempotent. Owner rotation is a separate one-off `update members set pin_hash = '<bcrypt>' where role = 'owner'`, applied out-of-band, never committed.
No identity fields are backfilled: Phase 8 deliberately requires each member to claim their own character ID.
