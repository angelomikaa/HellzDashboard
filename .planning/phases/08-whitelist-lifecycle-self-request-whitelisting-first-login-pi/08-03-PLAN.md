<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → setup-pin/request-access | User-controlled identity strings and image data |
| login 409 → first-access | Handle passed through client state only (no token) |
| request status → anon | Handle-only lookup, four fields maximum |
| localStorage → session | Only a server-validated session is persisted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-18 | Information Disclosure | PIN handling | mitigate | PIN only in component state; password inputs; never logged/persisted/URL |
| T-08-19 | Tampering | duplicate char IDs | mitigate | Client validates format only; server `duplicate_char_id` mapped inline |
| T-08-20 | Spoofing | request submission | mitigate | No session minted; approval staff-gated; UI states this explicitly |
| T-08-21 | Information Disclosure | status lookup | mitigate | Only four status keys rendered; no identity/PII |
| T-08-22 | Elevation of Privilege | client routing | mitigate | All gating remains server-side; routing only improves UX |
| T-08-23 | Tampering | proof payload | mitigate | JPEG-only + 2 MB client guard; server re-validates magic bytes and size |
| T-08-24 | Denial of Service | repeated submits | mitigate | Submit disabled while pending; server unique-pending index + lockout on setup |
</threat_model>
