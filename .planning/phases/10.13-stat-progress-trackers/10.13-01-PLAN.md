# Phase 10.13 Plan 01 — Stat Progress Trackers

**Requirements:** CARD-04 (progression view of the evidenced stats)
**Depends on:** Phase 07.2 (key-stat strip + foco), Phase 09/0073 (my_report /
my_card contracts), Phase 10.13 decisions
**Migration:** 0074 (`my_stat_progress`)

## Goal

The 12 stats a member sees in evidence (6 keys + 6 foco) stop being static
values: each tile carries a 3-point sparkline of the member's own history with
a hover read-out, and clicking any tile opens a progression modal that plots the
own history against three reference lines — class, function and cohort averages.

## Tasks

1. **Server — migration 0074**
   - `public.my_stat_progress(p_stat_keys text[]) returns jsonb`
     - member gate from the JWT (`no_member_claim` / `forbidden`), active only;
     - per requested catalog stat: `own_value`, `history` (last 3 submissions,
       newest first, `status not in ('rejected','discarded')`), and
       `class_average` / `function_average` / `cohort_average` with sample sizes
       (each `n >= 3`, rounded to 2 decimals);
     - latest-value basis identical to `my_report` (non-rejected/discarded,
       `submitted_at desc, id desc`), active members only;
     - `security definer`, internal gate, revoke public/anon, grant authenticated;
     - bookkeeping row + `notify pgrst`.
   - Manifest regenerated (`npm run migrations:manifest`).

2. **Data layer — `src/lib/api.ts`**
   - Closed types `StatProgressPoint`, `StatProgressRow`, `MyStatProgress`.
   - `fetchMyStatProgress(session, statKeys)` with the malformed-body guard
     (`fetchMyCard` precedent).

3. **Pure model — `src/features/dashboard/statProgress.ts`**
   - `evidenceStatKeys(card, focus)`: 6 keys in server order, then foco order,
     de-duplicated.
   - `buildProgressEvidence(keys, progress, card, report)`: joins the RPC rows
     with the opaque points/labels, falling back to `my_report` when the
     progress fetch failed.
   - `historySeries(history)`: chronological points for the chart.
   - `chartDomain(points, references)`: padded min/max (flat series safe).
   - `formatHistoryDate(iso)`: pt-BR `dd/mm` for the hover read-out.

4. **Chart — `src/features/dashboard/StatTrendChart.tsx`**
   - `sparkline` variant: 3-point polyline + last dot, non-scaling stroke.
   - `detail` variant: 320×140 plot, horizontal reference lines (classe silver,
     função gold, coorte purple), value labels, own series in accent red.

5. **Tiles — `MiniStatTile` / `KeyStatCard` / `FocusStrip`**
   - `history` prop renders the sparkline; `onOpen` makes the tile a button.
   - Hover/focus popover lists the 3 values + dates (the tile stays the same
     anatomy; the popover is `pointer-events-none`).
   - FocusStrip receives the already-computed `focus` list (single source).

6. **Detail modal — `src/features/dashboard/ProgressDetailModal.tsx`**
   - Accessible dialog (focus trap, Escape, backdrop, focus return) following
     `PlayerStatsModal`.
   - One section per evidenced stat: label + current value + points chip, the
     detail chart, a 4-row comparison (Seu valor / Classe / Função / Coorte)
     with the signed delta and sample size, and "Ver no painel" (jump).

7. **Wiring — `DashboardPage`**
   - Fetch progress once for `priorityKeySet(myCard)` in a separate effect that
     degrades to `null`; compute `focus` once; render the modal for the clicked
     stat (defaults to the evidence list).

8. **Tests**
   - `src/lib/statProgressMigration.test.ts` — static SQL locks.
   - `src/features/dashboard/statProgress.test.ts` — evidence order/dedupe,
     merge + fallback, chronological series, flat-domain safety, date format.
   - `MiniStatTile` render test: sparkline only with ≥2 points, popover carries
     the three values.

## Success criteria

1. Every evidenced tile with ≥2 history points renders a sparkline; hovering
   (or focusing) it lists the last 3 values with dates.
2. Clicking a key or foco tile opens the modal on that stat.
3. The modal shows the 12 evidenced stats, each with own history and the three
   distinct reference lines (class / function / cohort), sample sizes included.
4. A failed `my_stat_progress` fetch leaves the Painel fully functional (no
   sparklines, modal shows the values it can).
5. No key-stat config, no other member's value and no client rank math.
6. `tsc -b`, the full Vitest suite and `vite build` stay green.
