# Phase 10.13 — Stat Progress Trackers (CONTEXT)

**Inserted:** 2026-11-06 (owner request)
**Scope:** the Painel hero strip only — the six Stats-Chave tiles and the six
Foco de melhoria tiles become progression trackers. One new member-facing RPC
(migration 0074), no rank-math change, no change to `my_report`/`my_card`.

## Owner request

> "atualmente, as sessões stats chave e foco de melhoria são apenas expositoras
> de valores fixos - vamos torná-las em trackers de progressão - a idéia é ter
> pequenos gráficos simplificados com hover que mostra o histórico do valor (3
> ultimas submissões), e ao ser clicado, abre uma tela que mostra maior riqueza
> de detalhes, como por exemplo linhas adicionais que comparam o seu valor
> contra as médias da classe diretamente, contra a função e contra a coorte,
> para cada status dos 12 que estão em evidência para cada usuário"

## Decisions (owner, 2026-11-06)

| Decision | Choice |
|---|---|
| Averages | Three DISTINCT references: **Classe** = every active member of the same merged class (any build role); **Função** = every active member with the same build role (any class); **Coorte** = same merged class + build role (the `my_report.class_average` basis) |
| Detail surface | Accessible modal over the Painel (PlayerStatsModal pattern), not a new tab |
| History scope | Every submission the panel already counts: `status not in ('rejected','discarded')` — validated **and pending**. The newest history point always equals the value the card shows |
| Evidence set | 6 key stats (server order) + 6 foco stats (improvementFocus order), de-duplicated |
| Chart | Client-side SVG only — zero new dependencies |
| Aggregates | `n >= 3` gate per reference (the existing `data_sufficient` convention); below that the line is hidden and the sample size is shown |

## Constraints

- `SECURITY DEFINER` with the internal active-member gate; `revoke` from
  `public, anon`, `grant execute` to `authenticated` only.
- The RPC returns aggregates + the caller's OWN history — never another
  individual's values. Key-stat CONFIG stays out of every payload.
- Rank math stays server-side: points/OVR arrive opaque and are rendered
  verbatim; the client only formats values for the chart.
- Degrades silently: a failed progress fetch removes the sparklines/detail but
  never the grouped 57-stat view or the strips themselves.
