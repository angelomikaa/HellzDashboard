# Requirements: NeoFoot — Guild Stats Panel

**Defined:** 2026-10-07
**Core Value:** Each player can see, through their stat cards, exactly where they stand compared to players of the same class and function — and what they must improve to reach guild standards.

## v1 Requirements

Requirements for initial release (MVP — will be escalated later). Each maps to roadmap phases.

### Access & Auth

- [x] **AUTH-01**: Player can access the panel with their personal 4-digit PIN (stored hashed)
- [x] **AUTH-02**: Only whitelisted guild members can access; players from other guilds are blocked
- [x] **AUTH-03**: Owner can grant or revoke the officer (admin) role manually
- [x] **AUTH-04**: Officers can remove players, revoking their panel access
- [x] **AUTH-05**: Officers can validate or reject submitted registers before they count toward ranks

### Registry & Catalog

- [x] **REG-01**: Admin can register a character with name, class, and function/role (e.g. tank vs DPS) *(02-02: Personagens page — inline registration via updateCharacter on the safe projection; officer write path live-proven by 02-01 smoke matrix)*
- [x] **REG-02**: Class list is extensible by an admin (Ragnarok Origin adds classes over time) *(02-01: staff-only insert live via RLS; 02-02: add-class UI inserts and immediately refreshes the dropdown)*
- [x] **REG-03**: Stat catalog covers all 3 groups (General Stats, Quasi-Stats, Special) with flat and percent value types (~50+ stats, labeled FLAT/PERCENTUAL) *(02-01: 57 stats live, owner-validated OCR keys, pt-BR labels)*

### Data Input

- [x] **INPT-01**: Player can submit stats via guided 3-screenshot upload (General, Quasi, Special) with example shots shown beside input boxes *(02-03: guided 5-step wizard with example images beside every group's inputs, works with zero OCR — owner browser-verified)*
- [x] **INPT-02**: OCR auto-reads screenshots (client-side, region-based) and pre-fills values *(05-01..05-05: structural reader behind readScreenshot, permanent exact-value harness; owner UAT APPROVED 2026-10-12 — marked Complete by the Phase 5 verification chain per the 05-05 plan's key-link pin)*
- [x] **INPT-03**: Player must review and fix OCR results before submission is accepted (mandatory fix-up gate) *(02-03: 3-checkbox review gate — Enviar disabled until all groups confirmed; server re-validates via create_submission RPC — owner browser-verified)*
- [x] **INPT-04**: Submissions are stored immutably (append-only) as the source of truth for ranks and future deltas *(02-01: no update/delete paths exist; atomic create_submission RPC live-proven — valid → uuid, unknown key → rejected; 02-03: owner browser-verified append-only history — resubmission created a new row, oldest untouched)*

### Ranking & Rating

- [x] **RNK-01**: Admin can select exactly 6 key stats per class via toggle (independent set per class)
- [x] **RNK-02**: Key stats are hidden from members server-side (not just UI-hidden — DevTools must not leak them)
- [x] **RNK-03**: Panel computes the overall (OVR) from the 6 key stats of the player's class, with a normalization floor of 51 (never below 51)
- [x] **RNK-04**: Panel computes per-stat percentile rank within same class+function (rank-based points: `(count_below / (n-1)) × 99`, preserving EAFC feel at guild scale)
- [x] **RNK-05**: Ranks display an "insufficient data" state when too few validated players exist per class

### Comparison & Dashboard

- [x] **CMP-01**: Player sees their own dashboard with stat cards (mobile-first responsive) *(04-03: DashboardPage wired into the Painel tab, 1→2→3 column grid — owner browser-verified, UAT steps 1–5)*
- [x] **CMP-02**: Player sees per-stat comparison: their value, guild average for their class, best in guild, and percentile position (e.g. "you're in the bottom 30% of Assassins for CRIT") *(04-01 tested percentile phrase + 04-02 StatCard + 04-03; owner browser-verified, UAT step 4)*
- [x] **CMP-03**: Members see aggregates only — never other individual players' values *(04-03: owner DevTools-verified exactly one /rpc/my_report request with aggregates only — UAT step 6; no-key-stat-leak + import gates since 04-01)*

### Showcase

- [x] **SHWC-01**: Stat cards are tiered: bronze for mediocre stats, silver for mildly elevated, gold for highly elevated, platinum for top of the class (own visual identity, not a copy of the reference model) *(04-01 tier bands + 04-02 StatCard/TierLegend + 04-03; owner browser-verified, UAT steps 1/4)*
- [x] **SHWC-02**: Promotion page shows top players as EAFC-style cards to promote the best players in the guild

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Multi-guild support | Single guild, one panel — if demand appears, deploy a second instance instead of building tenancy |
| Chat / announcements / events | Discord/WhatsApp already do this better; panel is stats-only (core loop) |
| Real-time sync with the game / game API | Ragnarok Origin has no public API; scraping violates ToS — the screenshot+OCR pipeline IS the sync mechanism |
| Fully automatic OCR with zero manual review | Game UI fonts/backgrounds cause silent misreads that poison every rank built on them — mandatory fix-up gate is non-negotiable |
| Full account system (email/password, verification, reset) | Massive friction for a mobile guild community; per-player 4-digit PIN + whitelist is the boundary |
| Members viewing other individual players' raw stats | Destroys trust and privacy; members see aggregates only; promotion page is the sanctioned view of top players |
| Exposing which stats are "key" to members | Defeats anti-gaming design: members would min-max exactly the 6 key stats to inflate OVR |
| Complex ranking formula builder (weight sliders, pluggable math) | Exactly 6 key stats per class with admin toggles; formula builders create non-comparable historical ranks |
| Public (outside-guild) leaderboards | Exposes members' data beyond the trust boundary; no consent model exists |
