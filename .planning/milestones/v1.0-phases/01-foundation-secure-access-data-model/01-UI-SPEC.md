# Phase 1 — UI Design Contract: Foundation — Secure Access & Data Model

> Visual and interaction contract for Phase 1's single user-facing screen (the PIN Gate) plus the foundational design tokens all later phases (stat cards, comparisons, promotion page) build upon. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope anchor:** Phase 1's only UI is the PIN login screen, a minimal placeholder home, and logout (Plan 01-03). Tier-color tokens below are established now as *reusable foundation* (consumed in Phase 4+); they do NOT appear in Phase 1 screens.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — deliberate. Plan 01-03 locks "styling is deliberately minimal" and Plan 01-01 locks the scaffold (React 19 + Vite + Tailwind v4, no component registry). Initializing shadcn now would modify approved plans; it can be reconsidered at Phase 4 planning if richer primitives are wanted. |
| Preset | not applicable |

| Language | **pt-BR** for ALL user-facing copy (matches Plan 01-03's example copy "Entrar"/"PIN incorreto", the Portuguese reference dashboard, and D-09's Portuguese locale). Format numbers with `Intl.NumberFormat('pt-BR')` (e.g. `1.234.567`) from Phase 2 onward. |
| Theme | **Dark-only** (recommended default; no upstream decision exists). Rationale: EAFC Ultimate Team aesthetic, tier metals (bronze→platinum) read best on dark surfaces, mobile-gaming usage context. Light mode is out of scope for v1 — do not build a toggle. |

### Token implementation (Tailwind v4 CSS-first — no config file)

Declare all custom tokens once in `src/index.css` so utilities like `bg-dominant`, `text-accent`, `border-line` generate automatically and later phases reuse them without re-specification:

```css
@import "tailwindcss";

@theme {
  /* surfaces (60/30/10) */
  --color-dominant: #0D1117;   /* page background — 60% */
  --color-surface: #161B22;    /* cards, login panel — 30% */
  --color-line: #30363D;       /* borders, dividers */
  --color-accent: #E3B341;     /* interactive gold — 10% */
  --color-accent-foreground: #0D1117;

  /* text */
  --color-content: #E6EDF3;
  --color-muted: #8B949E;

  /* semantic */
  --color-destructive: #F85149;
  --color-success: #3FB950;    /* reserved: Phase 6+ */

  /* tier tokens (FOUNDATIONAL — consumed in Phase 4+, unused in Phase 1) */
  --color-tier-bronze: #B87333;
  --color-tier-silver: #B8C0CC;
  --color-tier-gold: #E9B44C;
  --color-tier-platinum: #D7E3F0;
}
```

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/inline gaps, badge padding |
| sm | 8px | Label↔input gap, inline element spacing |
| md | 16px | Default element spacing, gaps between form fields, page side-padding (mobile) |
| lg | 24px | Card interior padding, gaps between form groups |
| xl | 32px | Layout gaps, home view section spacing |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- **Touch targets: minimum 44×44px** for every interactive element (inputs, buttons) — the game is mobile and CMP-01 declares mobile-first responsive. Input and button height: exactly **44px**.
- Login card max-width: **384px**, horizontally centered, `mx-auto` with `px-4` page padding.

Exactly 4 sizes, 2 weights. System font stack (see Design System).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 (regular) | 1.5 | Input text, body copy, placeholder-home text |
| Label | 14px | 600 (semibold) | 1.4 | Field labels, error text, meta text, role badge |
| Heading | 20px | 600 (semibold) | 1.2 | Card/section headings |
| Display | 28px | 600 (semibold) | 1.2 | Login screen title ("NeoFoot" wordmark area) |

Rules:
- Button text: Body size (16px) at weight 600.
- Error text: Label size (14px), weight 600, `text-destructive`.
- No sizes/weights outside this scale in Phase 1.

## Phase 1 Screens & Interaction Contract

### Screen 1: PIN Gate (LoginPage) — the only real Phase 1 design

**Layout** (mobile-first, single column):
```
┌─────────────────────────────────────┐
│           (dominant #0D1117)        │  ← full viewport, centers card
│                                     │
│        ┌───────────────────┐        │
│        │      NeoFoot       │  28px Display, text-content, centered  │
│        │  ───────────────  │        │
│        │ [Usuário do Discord]│  label 14px semibold text-content    │
│        │ [_______________] │  input 44px, bg-surface, border-line   │
│        │ [PIN (4 dígitos)]  │  label                                 │
│        │ [••••]            │  input 44px, type=password            │
│        │                   │        │
│        │ (error line)      │  14px semibold text-destructive       │
│        │                   │        │
│        │ [    Entrar      ] │  full-width CTA 44px, bg-accent       │
│        └───────────────────┘        │
│        card: bg-surface, border 1px line, rounded-lg, p-24px, max-w-384px
└─────────────────────────────────────┘
```
- Card centered horizontally, upper-third vertically (`py-64px`+); vertical centering acceptable on short viewports.
- Field order: Discord handle first, PIN second (matches plan; login identity order D-01).
- Gap between fields: 16px (md). Label-to-input gap: 8px (sm). Card padding: 24px (lg).

**Field contract:**

| Field | Spec |
|-------|------|
| Discord handle | `type="text"`, `label "Usuário do Discord"`, `autoComplete="off"`, 16px input text |
| PIN | `type="password"`, `inputMode="numeric"`, `maxLength={4}`, `autoComplete="off"`, `label "PIN (4 dígitos)"`, pattern digits only |
| Submit | `"Entrar"` — `bg-accent text-accent-foreground`, 44px tall, full card width, disabled while a request is in flight (`aria-busy`) |

**State matrix:**

| State | Trigger | UI behavior | Copy |
|-------|---------|-------------|------|
| Idle | initial render | form enabled, CTA active | — |
| Submitting | request in flight | CTA disabled, inputs stay editable | — |
| Invalid credentials | 401 `{error:"invalid_credentials", attempts_remaining}` | error line appears directly above CTA (`role="alert"`, `aria-live="polite"`), PIN field cleared + focused; form stays enabled | `Discord ou PIN incorreto — {attempts_remaining} tentativas restantes.` / `… — 1 tentativa restante.` |
| Locked | 429 `{error:"locked", retry_after_seconds}` | error line above CTA; CTA disabled; inputs disabled (client hint only — server enforces regardless, D-07) | `Muitas tentativas incorretas. Tente novamente em {minutes} minutos.` (minutes from `retry_after_seconds`, rounded up; static display acceptable per plan) |
| Network/server error | fetch reject / non-2xx other | error line above CTA; form stays enabled for retry | `Não foi possível conectar ao servidor. Verifique sua conexão e tente novamente.` |

State-matrix notes:
- The 401 copy must **not** reveal whether the handle or the PIN was wrong (single `invalid_credentials` envelope; enumeration-safe per Plan 01-03's threat model T-01-03). Supersedes the plan's illustrative "PIN incorreto" example copy while preserving the locked must-have (attempts remaining shown, D-07).
- Server error copy deliberately avoids exposing free-tier internals (HTTP 540/pausing — RESEARCH PITFALLS).

### Screen 2: Placeholder home (post-login)

- Top bar: left `Olá, {display_name}` (16px, content) + role badge (`Membro`/`Oficial`/`Proprietário`, 14px semibold, muted, bordered pill); right **Sair** button (outline style, `border-line text-content`, 44px touch target — NOT accent).
- Body: placeholder copy (below).
- On `Sair`: `clearSession()` → immediately render LoginPage. No confirmation (see Destructive below).

### Session interaction rules (locked — D-06/D-07)

- Session persists across reloads (7-day localStorage, key `nefoot_session`) — never interrupt a logged-in user.
- **Expiry is silent**: expired session → `clearSession()` → LoginPage. Never show a "session expiring/expired" banner, toast, or text (D-06).
- Logout is one click, no dialog.
- Never display the raw JWT or PIN anywhere; PIN input is masked (`type="password"`) always.

### Accessibility contract

- All inputs have programmatic labels (`<label htmlFor>`); errors use `role="alert"` + `aria-live="polite"`; CTA uses `aria-busy` while submitting.
- `focus-visible` ring: 2px accent on all interactive elements — keyboard path: handle → PIN → Entrar → (error region announceable).
- Contrast: all text pairs listed above meet WCAG AA (≥4.5:1); accent CTA pair ≥7:1.
- No motion/animation in Phase 1 (nothing to reduce); any later animation must respect `prefers-reduced-motion`.

## Copywriting Contract

All copy in pt-BR.

| Element | Copy |
|---------|------|
| Primary CTA | `Entrar` (login submit button) |
| Placeholder home heading | `Olá, {display_name}` |
| Placeholder home body | `O painel de status está em construção — as próximas telas chegam em breve.` (Phase 1 has no data-driven views; first true empty states arrive in Phase 2 registry/catalog and are specced there) |
| Error state (wrong credentials) | `Discord ou PIN incorreto — {attempts_remaining} tentativas restantes.` |
| Error state (lockout, 429) | `Muitas tentativas incorretas. Tente novamente em {minutes} minutos.` |
| Error state (network/server) | `Não foi possível conectar ao servidor. Verifique sua conexão e tente novamente.` |
| Destructive confirmation | `Sair` (logout): **no confirmation** — clearing the session is low-cost and instantly reversible by re-entering handle + PIN. Future destructive actions (Phase 6 remove/reject) WILL require a modal confirmation; pattern reserved, not specced here. |
